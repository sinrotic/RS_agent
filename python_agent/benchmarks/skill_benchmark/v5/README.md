# 真实画像对照购物评测 v5

本版在修正后的冻结目录上增加“同需求、不同真实画像”的对照。150 个画像用户与原有训练/开发/测试归属不变；购物表达和后续回答仍是合成场景，不是复原的真人需求。本版不替换 v3/v4 文件，不修改生产商品库、画像或 Skill。

## 范围与交付

- [benchmark.json](benchmark.json)：900 件商品、150 个真实画像用户、1985 条任务、2705 个轮次。
- 新增 57 组双用户对照，共 114 条任务，来自 12 对、24 个真实用户；这些变体不是新的独立用户。
- 对照类型：历史授权选参考 9 组、证据不足时澄清 12 组、当前要求覆盖历史 12 组、送礼切换偏好对象 12 组、跨类目不能迁移偏好 12 组。
- [contrast-examples.json](contrast-examples.json)：下文三组实例的实际商品、历史证据、公式得分及相关澄清/覆盖/送礼场景。不导出保留测试组的答案。
- [audit.json](audit.json)：公式参考路径及数据范围审计，不是模型能力报告。
- [calibration/blind-review.md](calibration/blind-review.md)：120 对独立盲审材料，优先包含全部非测试画像对照。只用训练对照与开发任务，不用保留测试集补校准。[labels.json](calibration/labels.json) 尚未填写。

新对照沿用原画像的真实过去正向记录，按证据与现有可供商品确定性配对，不重新随机抽人，也不改变原先中上热度来源。没有编造年龄、职业、性别、设备型号或收礼人画像。

## 人与商品如何参与评分

只有顾客公开说“照我以前的习惯”时，才启用当前类目、完整路径内的画像奖励。其他购物任务继续沿用 v4 的当前需求评分；原始类目/店铺历史匹配仍只作诊断。顾客明确改变要求或替别人买时，禁用本人的画像奖励。

对一个正在评价的属性，例如笔尖粗细、有线/无线、目录的店铺标记：

```text
N = 当前类目内不同历史商品数
n = 其中有明确属性证据的不同商品数
P(v) = 属性值 v 的历史商品数 / n
coverage = n / N
c = n / (n + 2) × coverage
R(item) = 1 + c × P(item 的属性值)    # 已通过全部硬条件的商品
推荐分 = 100 × DCG / 冻结完整目录中的理想 DCG
```

计数按商品 ID 去重，使用画像截止前的正向交互，不把未来目标、Agent 自报喜好或同一商品的重复记录加进证据。属性未明确提及、文字互相矛盾时保持未知；未知属性没有画像奖励，也不当作已满足明确属性要求。

`c` 是工程上的证据折扣，不是统计概率。奖励、置信度和 NDCG 仍只是待人审校准的匹配代理，不代表真实满意度。预算和用户明确说“只要”的属性是硬条件，违反时整条任务推荐分归零，历史匹配不能抵消。

两个对照成员分别评分后，组分取两侧完整任务推荐分的较小值。缺一侧、澄清没完成或任一侧失败都不能用另一侧满分掩盖。不同商品 ID 本身不奖励；当前要求或收礼人相同时，两人完全可以得到同一款商品。

同一人的所有任务仍归同一任务族；一对用户的全部变体共享统计簇，运行报告和版本比较按该簇处理相关性，不把成对样本当两份独立证据。

## 三组实际例子

以下商品得分来自独立公式参考和对照计算，不是真实模型输出。所有数字均为数据源标价单位，原始币种未确认，不称为人民币或美元。

### 1. 同样买中性笔：0.7mm 与 0.5mm

两人都说：

> 想买中性笔，预算20以内，照我以前的习惯先给我选1款参考，不确定的地方说明就好。

画像 A（profile-family-012）有 3 件中性笔的过去正向记录，标题都明确为 0.7mm；属性覆盖率 100%，证据折扣 c=0.6。画像 B（profile-family-032）只有 1 件明确为 0.5mm 的记录，c=1/3，不能描述成稳定偏好。

商品 A 是 Pentel EnerGel 0.7mm 套装，价格 15.99；商品 B 是 ZEBRA Sarasa 0.5mm 套装，价格 12。

| 画像 | 推荐商品 A：0.7mm | 推荐商品 B：0.5mm |
| --- | ---: | ---: |
| A：3 条 0.7mm 证据 | 100 | 62.5 |
| B：1 条 0.5mm 证据 | 75 | 100 |

分别按证据选择，组分 100；把两人的结果互换，组分 62.5；给两人都推便宜的商品 B，组分也只有 62.5。不是“越贵越好”，而是当前顾客授权的粗细匹配参与了排序。

在对应的澄清变体中，两人都改为说：

> 想买中性笔，预算20以内，帮我挑1款，照我以前的习惯来；要是拿不准，先问我。

A 的证据较充分，可直接给参考；B 的单次记录不足，应问“这次想用什么粗细的笔尖？”。顾客回答“这次就要0.5mm笔尖，预算不变。”之后再选。具体澄清交互分 100，正确推荐分 100；泛问“有什么偏好”不能通过属性澄清检查，跳过澄清也不能完成任务。

### 2. 同样买耳机：无线与有线

两人都说：

> 想买入耳式耳机，预算80以内，照我以前的习惯先给我选1款参考，不确定的地方说明就好。

画像 A（profile-family-067）有 3 件明确为无线的入耳式耳机历史商品，c=0.6；画像 B（profile-family-001）有 1 件明确为有线的历史商品，c=1/3。

商品 A 是 Generic 无线入耳式耳机，价格 9.99；商品 B 是 UrbanX USB-C 有线耳机，价格 17.88。

| 画像 | 推荐商品 A：无线 | 推荐商品 B：有线 |
| --- | ---: | ---: |
| A：3 条无线证据 | 100 | 62.5 |
| B：1 条有线证据 | 75 | 100 |

证据不足且顾客要求拿不准先问时，B 应被问“这次想要有线还是无线款呢？”，收到“这次就要有线款，预算不变。”之后再推荐。

这里评的是连接方式匹配与参考选购，不声称已确认顾客手机的接口兼容。设备型号、接口适配、性能和推荐解释尚未全部纳入主分；不能把这个 100 分称为已验证最终可用。

### 3. 同样买耳机：不同店铺标记

顾客表达与上一组相同，预算同为 80；但两名用户不同。

画像 A（profile-family-002）在该类目有 1 件 Soundcore 的正向记录；画像 B（profile-family-006）有 1 件 cozoo 的正向记录。两边 c 都是 1/3，只能作薄证据参考。`store` 来自目录标记，不保证等同于真实销售商身份。

商品 A 是 Soundcore Liberty 无线耳机，价格 64.95；商品 B 是 cozoo 颈挂式蓝牙耳机，价格 19.99。

| 画像 | 推荐商品 A：Soundcore | 推荐商品 B：cozoo |
| --- | ---: | ---: |
| A：1 条 Soundcore 证据 | 100 | 75 |
| B：1 条 cozoo 证据 | 75 | 100 |

正确匹配两侧，组分 100；交换或不分人统一推荐其中一款，组分 75。由于只有单次证据，未匹配的合格替代品不判硬违规。

在“拿不准先问我”的变体中，两边都应先核实店铺偏好。在当前覆盖变体中，两人都说“这次只要 cozoo 家的，不要照以前的来”，则两边选 cozoo 都是 100，不能为了追求差异继续给 A 推 Soundcore。在送礼变体中，先问家人需求；若家人明确要 cozoo，两人也应按相同的收礼人要求评分。

## 类目错标修正

已修正 14 件目录商品的明确错标，并同步修正 7 件不同历史商品的对应分类、重算历史类目/店铺统计。每件保留原分类、原路径、标题证据与修正理由：

- Magene H603 胸带心率计：便携蓝牙音箱 → 心率计。
- Wi-Fi 信号扩展器：入耳式耳机 → Wi-Fi 信号扩展器。
- 5 件明确开放式、骨传导或空气传导耳机：入耳式 → 开放式耳机。
- Cross 和 Pen Savings 替换笔芯：整笔类目 → 笔芯。
- ARMIDO micro SD 存储卡：半球摄像头 → 存储卡。
- CB 麦克风与 SWR 表：车载电台主机 → 各自配件类目。
- 带触摸板的小键盘：键鼠套装 → 键盘；Post-it 分配器：便利贴 → 分配器。

修正后的心率计在音箱任务、开放式耳机在入耳式任务、笔芯在整笔任务中均因硬条件不符得 0，不再误得 100。不是把它们从候选中偷偷删掉，而是保留商品、修正商品事实与路径。

此修正覆盖已定位且有明确标题证据的矛盾，不等于 900 件商品全部获得语义认证；全目录语义审查仍待完成。

## 数据划分与限制

训练/开发/测试仍有 90/30/30 个真实用户。新对照分别为 34/4/19 组；考虑成对相关性后，全部任务的独立统计簇分别为 83/29/26。

开发集现有用户尚不能组成两侧都有可供商品、且偏好相反的授权对照，因此其新增组主要检查有证据/无证据时的行为适配及当前要求覆盖。不能宣称三个集合都充分覆盖了个性化敏感度；训练集可用于开发该规则，非测试训练对照已进入人工校准，保留测试仅用于候选确定后的复测。

历史画像、店铺和商品标签并非真实用户满意度标签；单次正向交互不证明稳定偏好，类目修正不证明性能、真实性、接口、电压、库存、配送或保修。当前澄清检查仍采用中文规则投影，必须人审，不是完整语义裁判。

本版可运行基线诊断，但 [pending-report.json](calibration/pending-report.json) 没有人审标签，不能授权有效性结论、正式自进化晋升或自动发布。旧 v4 的校准收据也不能复用于新数据与评分器。

## 复现与测试

在 `python_agent` 执行，输出必须使用新路径：

```powershell
python scripts/evaluation/skill_benchmark.py profile-contrasts --dataset benchmarks/skill_benchmark/v3/benchmark.json --out <新benchmark路径>
python scripts/evaluation/skill_benchmark.py contrast-examples --dataset <新benchmark路径> --out <新examples路径>
python scripts/evaluation/skill_benchmark.py audit --dataset <新benchmark路径> --out <新audit路径>
python scripts/evaluation/skill_benchmark.py calibration-pack --dataset <新benchmark路径> --pairs 120 --out-dir <新calibration目录>
```

验收覆盖类目错标、未知属性、真实画像证据校验、当前要求覆盖、具体澄清、条件回复、成对缺一侧计零、统计簇及工具来源。设置 `RS_BENCHMARK_TEST_JAVA` 为 JDK21+ 的 java 路径后，可运行包括真实 Java Loop 的受控模型工程验收；这不构成真实模型能力或业务效果评测。
