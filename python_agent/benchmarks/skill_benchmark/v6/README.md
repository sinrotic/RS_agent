# 顾客视角画像购物评测 v6

本版评价自然购物中的当前需求、弱历史证据和必要澄清，不再要求顾客说“照我以前的习惯”。画像来自隔离环境中已绑定且允许使用的 Profile User；当前明确要求和收礼人需求优先。可运行工程诊断，但独立相关性标注与人工校准尚未完成，不能据此自动晋级或发布 Skill。

## 数据范围

[benchmark.json](benchmark.json) 保留 900 件商品、150 个真实画像用户和原来的 90/30/30 用户划分，共 1999 条任务、最多 2761 个潜在 Turn。可选澄清分支直接推荐时会提前结束，潜在 Turn 数不等于实际对话长度。

64 组双用户对照共 128 条任务，仍来自 12 对、24 个真实用户：自然画像参考 9 组、可选偏好澄清 12 组、当前要求覆盖历史 12 组、送礼 12 组、无相关类目历史 12 组、关键兼容信息缺失 7 组。每组两人首条表达、硬要求、商品环境相同，仅真实历史不同；同一用户不跨集合，成对用户共享统计簇。

用户和商品沿用此前中上热度来源，未重新抽取或伪造用户。历史是截止时间前的正向评价，不证明购买、职业、年龄、设备型号或实际使用习惯。购物场景与后续回答是合成的顾客表达，不是复原的真人对话。

保留 v5 的已知类目修正及来源证据，不修改生产目录。目录整体语义审核仍待完成；本版不评价真实库存、运费、优惠、支付或配送。预算按冻结目录标价单位理解，原始币种未确认，不称人民币或美元。一款商品指一个商品条目，整包笔不伪装成单支售卖。

## 画像权限与需求来源

任务环境的 `profile_access` 保存允许使用的状态与绑定用户，不能靠顾客关键词开启画像。校验器拒绝跨用户绑定、缺权限的画像参考或把本人画像作为收礼人偏好。去画像实验同时隐藏请求快照、记忆工具中的历史与偏好，并关闭历史召回加权；当前 Session 信息仍保留。

顾客新说“这次只要0.5mm”后，该要求进入本轮硬条件，不再给历史属性加分。送礼可以在需求足够时给参考，也可以询问收礼人的相关偏好；不能用赠送者的历史推定对方喜好。

## 分层评分

| 层次 | 当前实现 | 结果解释 |
| --- | --- | --- |
| 硬条件 | 类目、完整路径、价格单位、预算、明确属性、数量与真实工具来源 | 明确违规不能被其他分数抵消；关键属性未知与明确不满足分别报告 |
| 当前条件与排序 | 保留冻结目录 NDCG；明确软要求沿用可验函数 | 没有独立标签时，满分只表示已标注条件满足，不表示用途体验或满意度最佳 |
| 独立推荐质量 | 接入人工批准的 0–3 相关性分级，用同一冻结目录计算 NDCG | 要覆盖全部硬条件可行商品；未标注不是负例，拒绝模型自评与错目录标签 |
| 历史证据 | 单独输出类目内属性的折扣匹配分、次数与覆盖率 | 不参与主分或晋级，不等于偏好概率；单次记录不会归一化成偏好满分 |
| 对话 | 必要澄清成功率、可选澄清次数与成功率、无谓追问率 | 低风险偏好不按历史条数强制追问；关键兼容信息必须确认 |
| 解释事实 | 有限规则检查价格、币种、历史断言、本人偏好误迁移及兼容保证 | 拦截可识别的错误；未被规则覆盖的语义不是已认证正确 |

历史证据分使用既有工程折扣，但与质量主分分离：

```text
N = 当前类目与完整路径内不同历史商品数
n = 其中有明确属性证据的不同商品数
P(v) = 属性值 v 的商品数 / n
c = n / (n + 2) × n / N
历史证据分 = 100 × c × 推荐属性的 P(v)
```

`c` 不是校准过的概率。硬违规的商品证据贡献为零；只提问、没有推荐时该指标不适用。当前场景中的“记笔记体验”和“通勤体验”在没有独立相关性标签时列为尚未评分的定性需求，不能从条件满分推导体验优秀。

同一 Skill 的画像消融比较只改变画像输入，保持任务、商品、模型配置、Skill、评分器和相关性标签相同。没有独立标签，或两侧获得了不同的顾客信息路径时，不计算个性化质量增益，不能用历史匹配差冒充质量提升。

## 澄清如何改变对话

低风险任务的首轮允许直接给合格参考，或提出一个相关偏好问题。直接推荐通过后任务结束，隐藏的后续偏好不会再发送。合法提问通过后才释放顾客答复；重复询问已知预算、索取无关个人信息或缺少相关问题会阻止继续。

对“要插在手机上用”的耳机需求，型号或接口未知属于关键缺口。必须先确认；顾客也不知道时，应指导查看设置、铭牌或说明书，不能直接保证兼容。此类成功的核实指导计交互成功，排序分不适用，不当作零分推荐失败。

问题评价接受规则覆盖的不同表述，不要求复述标准问句。当前仍是可审计关键词投影，不是完整语义裁判；自然问题的误判需要在盲审中发现和修正。

## 同需求不同画像的实际例子

完整商品、证据、双用户交叉评分及澄清分支见 [contrast-examples.json](contrast-examples.json)。以下均为实际目录与过去画像上的受控参考，不是真实模型推荐成绩。表中“条件分”未包含尚待独立标注的使用体验。

### 日常记笔记

两人的顾客表达相同：“平时记笔记用，想买中性笔，预算20以内，帮我挑一款。”

| 画像 | 可参考商品 | 条件分 | 历史证据分 |
| --- | --- | ---: | ---: |
| profile-family-012，3 款同类目 0.7mm 正向记录 | Pentel EnerGel 0.7mm，12 支装，15.99 | 100 | 60 |
| profile-family-032，1 款同类目 0.5mm 正向记录 | ZEBRA Sarasa 0.5mm，10 支装，12.00 | 100 | 33.33 |

两款互换时，仍满足目前的类目和预算条件，条件分仍为 100，历史证据分变为 0；这不把替代商品判成错误。Agent 可以先给参考，也可问“笔尖想用什么粗细？”得到答复后按明确粗细评分。

另有相同双用户任务：“这次只要0.5mm笔尖”。两人均应遵守本次要求；推荐 0.7mm 得 0，符合要求的 0.5mm 得条件分 100，不受旧历史影响。

### 通勤耳机

两人的顾客表达相同：“上下班路上用，想换副入耳式耳机，预算80以内，帮我挑一款。”

| 画像 | 可参考商品 | 条件分 | 历史证据分 |
| --- | --- | ---: | ---: |
| profile-family-067，3 款无线耳机正向记录 | Generic 无线入耳式耳机，9.99 | 100 | 60 |
| profile-family-001，1 款有线耳机正向记录 | UrbanX USB-C 有线耳机，17.88 | 100 | 33.33 |

单次有线记录不强制本次选择有线，也不证明手机支持 USB-C 数字音频。可选问题是“这次想要有线还是无线款？”如果需求改成“要插在手机上用”，两人都必须被问到手机型号或接口。顾客回答不知道时，核实指导交互分 100，排序不适用；凭空保证兼容则失败。

### 只有一次店铺记录

仍用上面的通勤需求，另外两名真实用户各只有一次相关店铺记录：profile-family-002 的目录店铺标记为 Soundcore，profile-family-006 为 cozoo。对应参考为 Soundcore Liberty 64.95 和 cozoo 无线耳机 19.99；两款条件分均为 100，各自匹配历史时证据分仅 33.33。

这里不把目录的 `store` 标记自动当成经过认证的品牌忠诚。两人推荐同一款也可以合理；不能因为商品 ID 不同而奖励。送给家人时不使用本人店铺历史；如顾客随后明确说对方要 cozoo，两人都按对方要求选择。

## 标注与晋级门槛

[relevance-review.json](relevance-review.json) 提供 40 条非测试任务的空白独立相关性标注，未填任何质量真值。[calibration/blind-review.md](calibration/blind-review.md) 提供 120 对非测试盲审候选；[labels.json](calibration/labels.json) 同样保持空白。人工合理性判断仍不等于真实个人满意度。

完成相关性标注后，显式导入会生成新题集，不覆盖旧版；需要重新绑定评分校准收据，也不会自动批准整个题集。[audit.json](audit.json) 的参考路径通过，但当前仍有场景审核、独立相关性、人工校准和完整目录语义审核门槛，`auto_deploy=false`。

训练与开发任务用于改进，保留测试用于候选确定后的复测。现有开发用户仍缺少两侧都有相反属性证据且目录可供的完整画像对照，不宣称三个集合都充分覆盖个性化敏感度。12 对用户的反复变体也不能算作新增独立用户。

## 复现入口

在 `python_agent` 下执行；输出路径须是新文件，命令拒绝覆盖已有冻结产物。

```powershell
python scripts/evaluation/skill_benchmark.py naturalize --dataset benchmarks/skill_benchmark/v5/benchmark.json --out <新题集路径>
python scripts/evaluation/skill_benchmark.py natural-examples --dataset <新题集路径> --out <样例路径>
python scripts/evaluation/skill_benchmark.py relevance-pack --dataset <新题集路径> --tasks 40 --out <标注路径>
python scripts/evaluation/skill_benchmark.py relevance-apply --dataset <新题集路径> --review <人工完成的标注路径> --out <带标签的新题集路径>
python scripts/evaluation/skill_benchmark.py compare-profile --hidden <去画像运行报告> --visible <真实画像运行报告> --out <消融比较路径>
```

真实模型运行的 `run` 命令增加 `--profile-visibility visible|hidden`。旧版与候选 Skill 对比必须使用相同画像可见性，不能把画像输入变化归因于 Skill 改进。测试证据与范围见 [verification.json](verification.json)。
