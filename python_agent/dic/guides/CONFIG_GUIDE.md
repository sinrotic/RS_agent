# 配置目录规范

本文档说明项目配置文件的放置和命名规则。

## 1. 统一目录

项目配置统一使用：

```text
configs/
```

不建议同时使用 `config/`、`configs/` 和 `config/configs/`。如果后续确实需要引入其它框架要求的 `config/`，必须在本文档中说明边界。

## 2. 推荐分层

```text
configs/
├─ data/
├─ ranking/
├─ recall/
├─ simulation/
├─ agent/
├─ demo/
└─ paths/
```

当前已有配置可以先保留原位置，避免一次性移动导致脚本引用断裂；后续新增配置按上述分层逐步落位。

## 3. 命名规则

- 可提交配置优先使用能表达阶段和用途的文件名。
- LOPO 配置文件名必须包含 `lopo`。
- 一次性搜索、网格调参或临时实验配置使用 `_tmp_*.yaml`，并在任务结束后清理。
- 配置字段使用小写 `snake_case`。
- 不把绝对路径、个人机器路径、密钥或临时调参值写入默认配置。

## 4. 迁移规则

如果需要把旧配置移动到新分层，必须单独执行：

1. 搜索代码、脚本、文档中对旧路径的引用。
2. 小批量移动同类配置。
3. 更新引用路径。
4. 运行相关最小 smoke 命令验证。
5. 检查 `git diff`，确认没有误改业务逻辑。
