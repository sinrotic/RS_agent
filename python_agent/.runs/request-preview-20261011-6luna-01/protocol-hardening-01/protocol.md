# 七条预览请求协议 v3

本协议用于原有七条合成顾客原话的提取和预审回归。不是正式评测 gold，不修改正式评分权重，不扩量，不导入正式评测集，不自动批准或上线。v1/v2 历史结果仍可只读校验；本轮模型必须输出 v3。

## 输出与职责

提取轮只收到 `customer_message`。根字段为 `schema_version`、`intent`、`context_facts`、`answer_requirements`、`requirements`、`unknowns`、`clarification`、`recipient`。提取者不能读取商品、历史画像、旧审核或 Codex 草案。

预审轮收到顾客原话、该轮原始提取、原有匿名商品目录和画像上下文。四个维度是自然性、提取忠实度、事实边界、澄清策略；逐维给理由、逐字证据和问题列表。两轮虽然使用不同上下文，但都由 `gpt-6-luna` 执行，不能宣称模型独立或把全 pass 当独立人工标注。

程序分别保存原始响应、规范化副本、规范化变更记录、逐字引用位置和协议错误。审核看到原始提取而不是程序修正后的内容。

## 字段与单位

约束字段采用注册词汇。`price` 不是自由 `budget`，`length` 不是自由 `cable_length`；注册别名可由程序透明规范化，未知字段必须隔离复核，不能随意归到某个已知维度。完整注册表见同目录修订文件的 `contract`。

长度统一以米存储：英尺/ft × 0.3048、厘米 × 0.01、毫米 × 0.001。例如“大概50英尺”规范为 `length / approximate / about / 15.24 / m`。换算不改变近似强度，不生成容差、余量或严格上限；原始数值、单位和原话保持在原响应及变更记录中。长度缺单位不猜。

价格币种明确才保存币种代码，否则 `null`；不能因为请求是中文或目录有价格就假定人民币或同币种。`purchase_quantity` 与 `recommendation_count` 分别计购买数量与推荐候选数量；口语单数不默认变成硬过滤。已有两根线不是要买两件。

操作系统、用途、预算和长度应进入可评分条件；设备故障、自述现状和备选方案属于背景。程序能检查注册字段的错放，不能保证发现被任意背景名称隐藏的语义遗漏，仍需模型审核和人审。

## 逐字证据

所有 `quote` 与 `intent.evidence` 必须是顾客原话的连续子串，不能拼接、改标点或加入省略号。顾客原话本来包含的省略号允许保留。程序汇总全部不合法引用，而不是发现第一个就掩盖其他错误；不自动修复引用。

证据位置由程序计算，使用从零开始的 Unicode 码点半开区间 `[start,end)`，多次出现时记录第一次位置。它不是 JavaScript 的 UTF-16 字符索引。位置存在仅证明逐字引用，不证明字段、意图或强弱解释正确。

## 回答目标与局部澄清

`answer_requirements` 含 `kind, need, quote`。种类为推荐、比较、解释、核查步骤、决策支持、兼容结论。用户“不确定哪种更合适”要记录条件式取舍，不能只罗列比较指标，也不意味着必须直接选唯一商品。

未知信息通过 `needed_for` 绑定真正依赖它的动作，并区分当前答案必需、具体商品结论才必需、可选优化。绑定未来动作的型号未知，不阻塞当前通用方法。绑定本轮已请求动作的必要缺口，必须将该动作放入 `unresolved_actions`，不能降为可选追问。

v3 中 `required_for_requested_answer` 的作用范围由 `needed_for` 决定：某个兼容结论必需的信息，不等于所有解释都必需。部分回答模式可以带这种动作局部的必要槽位，但必须暂缓对应动作，并以 `required_for_action` 追问完整覆盖。整条都不可答才用 `required_before_answer` 和 `blocking`。程序保留原标签，不把原始输出改成另一等级。

例如“扁平线好走门边吗？那个转接头能用吗？”：比较和核查方法可以先答；具体接头兼容结论暂缓，需要追问接头身份及两根现有线的接口。使用 `answer_partially_then_clarify`，追问标为 `required_for_action`。不能只问线、不核对“那个接头”是谁，也不能用目录中的接头替代不明指代。

相反，“该先核对哪些型号和尺寸？”只要求核查步骤，不自动扩大为现场兼容结论；缺设备型号不应成为解释步骤的门槛。

## 画像适用性

`recipient` 额外包含 `profile_reason`。`self` 仅说明购买/使用对象，不证明购物历史与当前任务相关。

本轮预览采用保守边界：有 `recommend` 动作时，只有本人、授权且相关的历史才允许条件式弱参考；提取轮没有历史，不能宣布相关性已经确认。纯技术比较和核查方法用 `not_relevant`，不奖励强行使用历史。赠送朋友时用 `do_not_transfer_to_recipient`，不能把赠送者偏好转移给朋友。

这是本轮预览的门槛，不是声称所有比较任务都与画像无关。后续若支持真正个性化的商品比较，应另定义与授权、证据、相关性绑定的适用规则和独立对照任务，而不是放松本轮结果以追求通过率。

当前明确需求始终优先。历史正向评价不证明购买、设备型号、收礼人喜好或稳定偏好。

## 预览门槛

必须满足：v3 提取与审核结构合法、全部逐字引用合法、字段单位可规范化、局部澄清和画像规则一致、审核四维全 pass 且问题列表为空、返回模型正确且结束标记为 stop。满足后仅进入“待独立人审”，否则隔离。旧包状态不改变。

程序不认证语义真值，七条回归不能证明真实表达覆盖、推荐质量或评分校准已经完成。接入自进化前仍需独立质量标注及推荐执行对照。
