# ADR-0020：将原多路召回产物接入 Java 首页

补充预算口径：96 为基础排序候选预算；反馈重排保留当前批次的既有机制可附加当前商品，不将该数字解释为所有场景下的硬上限。

2026-09-13，用户要求按原方案补齐召回。承接 ADR-0018、0019：首页增加 ItemCF weak/strong、Swing、UserCF、离线类目索引和 Popular；保留双塔、BGE、Catalog 探索、明确反馈和交付去重。协同方法负责行为扩展，UserCF 只在至少三项正向历史且有对应离线候选的用户上返回结果，热门仅补个性化候选缺口。

原 Python 候选库接口定义了按商品邻居、用户候选、类目和热门查询的边界，但 Java 没有接入，部署数据库的候选表也为空。本次将已有 train-only 产物流式转换成版本化只读 SQLite 索引，由专用内部 HTTP 服务提供这些查询；没有在请求中扫描 JSONL，也没有复制几千万条候选到内存或改写 MySQL 业务表。此选择降低导入与回滚的耦合成本，代价是增加一个需要独立部署和监控的运行时。

用户授权覆盖本次 Java 首页的有限预算接入；新增 serving manifest 保留原产物路径、哈希和状态，不修改原 pool500 诊断门禁，不声称原离线评估已证明该首页效果。UserCF、Swing 等原有门禁与本次功能接入验收分开记录。Co-visit 现存 v0 诊断切片不等同文档所述 v2 正式产物，暂不启用；标题类目扩展按原方案合并于语义路线，不增加同义独立来源。

每路按原得分检索，ItemCF 使用最近十项种子和 0.85 时间衰减，Swing 保留原边得分；同路重复商品取最大分。多路候选交错进入最多 72 个兴趣候选位，再由真实 Catalog 探索补到 96 个排序候选，最终仍经过 BGE 和多样性处理。原离线类目画像用于类目索引查询。明确喜欢后的找相似仅请求商品邻居来源，避免用户级离线画像覆盖即时意图。

Catalog 回填按每批最多 100 个 ID 执行。Trace 保存真实多来源贡献，重叠来源的计数之和可超过去重候选数；内部诊断接口不再平均分配虚构数量。新增运行时故障显式降级至原首页路线。配置开关可独立关闭新增六路。
