# RS Agent 能力提升候选方向

记录日期：2026-10-11。状态：候选讨论，待结合用户提供的方案确定实施范围。

RS Agent 适合围绕执行可靠性、上下文管理、观测与评测继续深化。优先把这些能力连成可验证的改进闭环，再扩展长期记忆和多 Agent 协作。主要实施入口为 Java Agent；Python 原型和实验可提供参考。

## 优先级与范围

| 顺序 | 方向 | 当前基础 | 建议补充的能力 |
| --- | --- | --- | --- |
| 1 | Harness 执行可靠性 | Agent Loop、Hook、工具编排和中断入口 | 重复调用检测、无进展判断、结果预算与失败恢复 |
| 2 | Agent 评测 | 已有评测代码、评测设计材料和真实验收记录 | 固定任务集、失败分类、质量与成本联合对照 |
| 3 | 可观测性与归因 | Trace 含工具、Agent、耗时、token 和缓存字段 | 调用树、有效参数指纹、证据增量与瓶颈定位 |
| 4 | 上下文压缩 | Effective Context、Context Checkpoint 和安全压缩边界 | 约束保留、工具结果压缩、长对话质量与缓存对照 |
| 5 | 长期记忆闭环 | Memory Item 存储和索引基础 | 跨 Session 检索、偏好更新、冲突处理、过期与删除 |
| 6 | 多 Agent 职责与上下文隔离 | RsAgentLoop、RagAgentLoop 和 call_agent | 任务交接、上下文预算、结果契约与取消传递 |
| 7 | 混合检索与证据质量 | BM25、向量检索、融合和 rerank 路径 | 商品召回与解释证据分别评测，定位融合与重排收益 |
| 8 | 事件协议与实时交互 | SSE、公开响应投影和 A2UI | 执行状态、取消、重试、恢复和请求幂等的协同 |
| 9 | 模型服务与推理优化 | 模型服务、量化和性能实验记录 | 固定负载下比较延迟、吞吐、显存与回答质量 |
| 10 | Agent SFT 与 RL | 可从已有执行链路积累轨迹 | 先形成可复核的轨迹和评测，再判断训练收益 |

顺序代表投入优先级。首轮将 Harness、评测和 Trace 一起推进，评测与观测为执行策略提供依据。

## 首轮建议

### Harness 执行可靠性

真实编排验收出现过单次请求六次 `rag_evidence_search`、多轮请求三次 `call_agent`。调用次数只是诊断线索；是否重复需要比较查询、候选集合、过滤条件、偏好版本和证据目标。[验收与收益边界](../../reports/agent-orchestration-optimization-20261011/README.md)

建议在既有 Loop 和 Hook 上增加以下控制：

- 对同一 Turn 内有效输入相同、已成功完成的只读调用，评估结果复用；新交付、“换一批”、用户或偏好变化须分别处理。
- 用滑动窗口观察调用参数和证据增量，识别反复执行却没有进展的模式。
- 首次检测后向模型提供已有事实、缺失信息和预算提醒；持续无进展时选择换策略、追问或明确说明信息不足。
- 按工具类型限制进入模型上下文的结果大小，保留关键商品事实、证据对应关系和失败信息。
- 区分可恢复的工具失败与终止错误，设置有限重试并传递取消。

验收重点：重复只读执行是否减少，任务完成率和约束满足率是否保持，工具失败后的恢复是否有效。不能仅凭调用次数或检索结果为空就宣布任务完成。

### Agent 评测

先建立覆盖普通推荐、预算与属性约束、解释比较、多轮修改、换一批、空检索、工具失败和取消重试的固定任务集。后续增加长对话与跨 Session 记忆场景。

对商品真实性、预算、重复商品和输出结构使用确定性检查；对解释是否有证据、是否满足需求采用明确评分标准，并保留人工复核样本。LLM-as-Judge 可提供辅助评分，需校准其一致性。

同一批任务同时记录完成率、约束满足率、证据支持情况、模型与工具调用次数、token、首个可见输出时间和完整回答时间。每个策略独立对照，固定模型、提示词、任务输入和负载，记录缓存状态及输出长度。

验收重点：能复现改动前后的差异，能定位质量回退，能解释收益来自哪里。样本规模需足以支持所报告的统计量。

### 可观测性与归因

在已有 Trace 上补全 Turn、模型调用、工具调用和子 Agent 的父子关系，并记录配置版本、有效参数指纹、结果规模和证据增量。参数指纹应隔离用户与 Session 范围；内部诊断信息遵循现有投影边界。

建议支持按一次失败任务查看完整调用树，分别统计模型规划、工具等待、实际执行、上下文处理和持久化耗时。缓存命中字段需验证真实采集链路，不能只凭字段存在认定数据完整。

验收重点：可以从一条失败或慢请求定位具体阶段，并准确关联模型、工具和子 Agent 的错误与成本。是否接入 Langfuse 后续根据方案决定。

### 上下文压缩

围绕现有 Effective Context 设计，保留当前需求、约束修改、已确认事实、近期事件和完整工具调用配对。对历史摘要和长工具结果分别制定压缩策略，并比较固定提示前缀稳定性与实际缓存复用。

验收重点：长对话中预算、排除项、偏好修改和工具结果关联是否保留；比较压缩前后 token、实际缓存命中、延迟和回答质量。压缩与缓存之间的收益需要实测。

实现须遵循 [安全压缩边界](../../adr/0003-compaction-only-at-safe-model-call-boundaries.md) 与 [可审计裁剪](../../adr/0004-auditable-lossy-context-truncation.md)：在事件持久化且没有未完成工具调用时切换有效上下文，有损裁剪保留审计记录和权威历史。

## 后续扩展

### 长期记忆闭环

让 Long-term Memory 以用户为范围跨 Session 使用，明确哪些事实允许写入、如何更新冲突偏好、何时过期以及如何查看和删除。Session Preference 与 Profile Preference 按既有领域定义分别处理。[领域词汇](../../../CONTEXT.md)

验收覆盖跨 Session 偏好复用、用户修改偏好、删除后停止召回、过期和不同用户隔离。命中率需事先定义相关记忆和统计分母。

### 多 Agent 职责与上下文隔离

先明确主 Agent 的需求理解与最终交付职责，以及证据 Agent 的候选范围检索职责。子任务只传递必要查询、候选和约束，以受限结构返回证据、未解决问题与状态。

验收对照单 Agent 和职责拆分方案的质量、token 与耗时，检查结果交接、超时和取消。调用后端服务与拥有独立决策循环的 Agent 在方案中应分别说明。新增拆分要能解决明确问题。

### 混合检索与证据质量

分别评估商品召回和候选范围内的 RAG Evidence：前者衡量候选相关性与排序质量，后者衡量解释所需证据的覆盖与正确性。比较 BM25、向量、融合与 rerank 的独立贡献，记录候选数和耗时。

验收采用带相关性标注的任务与固定商品范围，可使用 Recall@K、NDCG@K 等指标；解释证据不得自行新增或提升候选商品。

### 事件协议与实时交互

延续现有 SSE 与公开投影，明确开始、进度、回答、失败和取消状态，以及连接中断后的状态查询或恢复行为。请求幂等、重复点击控制和实时反馈共同处理重复提交。

验收覆盖事件顺序、最终状态一致性、取消和重试不产生重复 Turn 或交付，以及公开流不泄露内部载荷。扩展公开事件或区块时同步更新 [响应投影契约](../../adr/0012-public-agent-response-projection.md)。

AG-UI 是交互事件协议，A2UI 是生成界面的规范，两者可以协作；采用 AG-UI 不要求统一改为 WebSocket。[AG-UI 官方说明](https://docs.ag-ui.com/introduction)

### 模型服务与推理优化

选择 Agent 当前瓶颈中的模型调用或 rerank 阶段，以固定输入和负载比较量化、批处理、缓存或并发配置。分别报告模型直连和完整 Agent 流程，保留质量对照。

验收包含显存、吞吐、并发条件、输出长度、错误率与延迟分布；不得将单次模型生成的收益直接换算为完整任务收益。本机任务遵循 12GB 默认可承受、14GB 上限的资源规则，超出时使用限流 smoke 或远程环境。

## Agent 训练的启动条件

先用评测证明主要失败来自模型的决策或工具使用能力，并形成有来源、可复核且与评测集隔离的训练轨迹。随后再比较提示词、运行时控制、SFT 与 RL 的收益及成本。

Agent 轨迹训练与推荐排序模型训练具有不同目标，需要分别定义数据、奖励和验收。图片中的 RaR、Loss Mask、GSPO 等方法待用户提供方案后再评估。

## 后续方案对照

收到方案后，逐项核对目标问题、现有能力复用、模块边界、数据与模型资源、失败处理、评测和上线范围，再确定采用、调整或暂缓的部分。

当前记录中的数值线索来自仓库验收，不是改进承诺。完成率、RT 降幅、记忆命中率和用户规模均使用项目实测；截图中的示例数字不作为本项目结果。

Agent 水平扩展若涉及多个活跃实例，需单独处理 [单活实例决策](../../adr/0007-first-release-uses-one-active-agent-instance.md) 中规定的会话写入正确性问题。
