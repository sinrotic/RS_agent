# 2026-09-08 换批仍是相同商品的修复

用户反馈点击“换一批推荐”仍推荐相同的东西。本次检查真实交付，确认不是页面未更新：00:24:10 和 00:24:22 两批共 12 个 ID 不同，却全是电脑背包。CoolBELL 两款同型号只换颜色，LOKASS 两款换尺寸且主图相同。两批各覆盖 3 个 Catalog 类目，因此上次“ID 不重复、类目数大于 1”的验收漏掉了实际体验。

## 根因与修复

- 同款变体使用不同 ID、不同 Catalog 类目，绕过原有去重与类目限制。新增首页内容选择策略，按品牌／型号与长标题相似度识别同款，并检查最近多批内容。
- 该画像有背包和墨盒两种正向历史，但模型排序固定取第一个查询。换批根据上一批内容选择差异更大的已有兴趣，不改为无依据的随机商品。
- 原“探索席位”按是否有偏好加分判断，语义背包也能被算作探索。现在初始六项页至少预留 2 个、换批至少预留 3 个真正 Catalog 探索候选（候选足够时）。
- 前端喜欢与换批原来复用 `feed:`。现在喜欢发送 `similar:`，换批发送 `feed:`，不感兴趣发送 `rerank:`；后端统一校验归属及过期。
- 保留首屏品牌和类目限制，覆盖 20 项页面首屏排序；内容过滤后为空时返回可重试错误，避免禁用换批并误报目录耗尽。

## 验收

1. 固定真实交付只读回放稳定失败：`different item_ids with same image cross consecutive batches`。商品事实与脱敏身份摘要见 [修复前证据](../evidence/2026-09-08-home-refresh-repetition-before.json)。
2. 回归测试先复现同型号换色穿透，再修复；将真实商品标题与型号保存为测试夹具。Recommend 全部 **83 项通过**，前端 **23 项通过**，构建通过。
3. 使用同一真实历史画像、线上 Catalog／Milvus／BGE，在独立 Recommend 实例中回放，交付和偏好使用内存隔离：三批各 6 项，探索数量为 **2／3／3**，背包数量为 **4／0／2**；第二批出现墨盒兴趣及探索商品。三批 ID 和主图均不重复，耗时 **1104.8／1004.5／910.8 毫秒**（有限样本，包含商品回填）。真实交付计数不变。见 [修复后回放](../evidence/2026-09-08-home-refresh-content-after.json)。
4. 部署后真实 Chromium 页面验证连续三批 18 个不同 ID、不感兴趣后过滤补满、喜欢走 `similar:` 找相似；保存 [浏览器实际标题与图片](../evidence/2026-09-08-home-refresh-browser-after.json)。测试偏好已撤销并登出。
