# 参考 YouTube 的三塔结构设计

日期：2026-10-11。状态：骨干已实现并完成分阶段实验，未部署。承接三塔总方案及 `docs/reports/three-tower-20261011/README.md` 的 smoke 结论；本设计不改变 ADR-0019 已部署的 queryv2 路由。

执行补记：完成推荐单任务的独立用户确认和三塔代理对照，详见 `docs/reports/three-tower-product-v3/README.md`。推荐在有界评估上获得正向证据；三塔调整为语义权重 0.1、Query 学习率 2e-6 后保住本轮推荐指标，语义仍缺独立相关性验收。后续候选项以报告中明确列为已做的内容为准。

## 依据与边界

YouTube 2019 NDR 的左塔汇聚当前视频与用户观看历史，右塔编码候选视频。视频 ID、频道等类别特征经 embedding 转换；历史 ID 向量取均值；同类 ID 在历史与候选侧共享。两侧前馈网络输出归一化向量，以批内 softmax 和采样概率校正训练，候选向量可预计算并索引。其 query tower 表示用户上下文，不能与本项目自然语言 Query 塔混称。[原论文 §3、§5、Figure 2](https://storage.googleapis.com/gweb-research2023-media/pubtools/5716.pdf)

这里借鉴“可训练商品表示、历史聚合、独立请求网络、点积召回”，不照搬视频观看场景或宣称复现 YouTube。BGE、残差结构、下述维度及初始化均是本项目设计。

仓库 `_TorchYouTubeDNN` 已有可训练商品表和用户残差；`_TorchDSSM` 也有用户/商品残差。前次 smoke 同时改变表示来源、压缩维度、用户残差和训练任务，无法将失败单独归因于多任务。

## 首选骨干：BGE + 三个残差 MLP

设 `norm` 为带 epsilon 的 L2 归一化，所有 BGE 输入使用固定文本模板、tokenizer 和长度，BGE 第一阶段冻结。商品缓存为 `x_i=norm(BGE(text_i))`，需求向量为 `x_q=norm(BGE(query))`，维度均为 1024。

| 模块 | 输入 | 可训练结构 | 输出 |
| --- | --- | --- | --- |
| Item | 商品 BGE 向量 x_i | A_i：Linear(1024,256) → ReLU → Linear(256,1024)，与输入相加 | v_i=norm(x_i+A_i(x_i)) |
| User | 历史商品经上述 Item 得到的 v_h，按 mask 取均值 m | A_u：Linear(1024,256) → ReLU → Linear(256,1024)，与 m 相加 | u=norm(m+A_u(m)) |
| Query | 需求 BGE 向量 x_q | A_q：Linear(1024,256) → ReLU → Linear(256,1024)，与输入相加 | q=norm(x_q+A_q(x_q)) |

三个 A 使用独立参数，只有 Item 在两项任务及历史/候选两种用途之间共享。隐藏维度 256 是有界起点，不是论文固定配置。首轮不使用 Dropout 或改变跳连输出的 LayerNorm，以便严格验证初始化等价性。

每个 A 的第一层正常随机初始化，最后一层权重及偏置初始化为零。这样起始时 `v_i=x_i`、`q=x_q`、`u=norm(mean(x_history))`；在相同输入、候选域和过滤下应复现原 BGE＋历史均值分数。最后一层可以先收到梯度，后续第一层也可学习，不能把整个两层网络同时置零。

保持 1024 维是诊断选择：先排除随机降维造成的初始退化。成本是索引大于 128 维方案，不能直接复用线上 64 维双塔集合；后续用独立实验比较 256/128 维压缩及蒸馏。残差并不保证训练后语义能力自动保留。

## 历史表示与梯度

历史最多 50 件正反馈商品，严格早于目标时间；先做 masked mean，时间衰减和注意力各自另开对照。这里仍是集合聚合，不声称已建模顺序。空历史不输出伪个性化向量，走已有冷启动回退；缺失文本/未知商品的覆盖单列。

缓存只保存冻结的 BGE 输出。训练时将本批历史、正例、负例的商品 ID 去重，取 BGE 缓存后重新执行可微 Item 前向，再按索引还原各路径。不得把旧 Item 输出缓存直接用于历史而仍声称历史商品编码器端到端训练。

推荐损失更新 User，并从历史路径和候选路径共同更新 Item。语义损失更新 Query 和候选 Item。语义更新不会直接修改 User 参数，但会改变它下次接收的历史商品表示。两个任务均不更新冻结 BGE。

评估和导出时可以预计算当前 checkpoint 的 Item 向量，历史与候选必须使用同一版本；User 线上也消费同样归一化的 v_i。避免旧 queryv2 的训练/导出表示差异在新实验中再次出现。

## 商品 ID 增强：单独验证

在以上骨干上加入可关闭的商品 ID 分支：

`e_i=Embedding(item_id,64)`

`v_i=norm(x_i+A_i(x_i)+W_id(e_i))`

W_id 为无偏置 Linear(64,1024)。ID 表小随机初始化，W_id 初始化为零，使初始语义基线保持一致；不能把两者都置零，否则该分支失去有效梯度起点。历史/候选共享同一 ID 表和 Item 函数。未在训练词表中的商品令 ID 分支严格为零，由文本分支编码；OOV 不复用任意已训练商品行。

文本可以帮助内容理解与新商品表示，ID 给常见商品提供独立的行为调整量；这只是机制假设，ID 是否改善长尾或整体效果必须验证。ID 分支也接收语义损失，不为两任务偷偷使用不同 Item 向量。先比不加 ID 与加 ID；若语义受损，再对 ID 正则、训练时 ID dropout 做独立消融。

三个残差 MLP 共约 158 万参数。ID 分支额外约 `64N+65,536` 参数；N=864,288 时，仅 FP32 ID 权重约 0.22 GB，带梯度和 Adam 两个状态约 0.89 GB（十进制字节估算，不含缓存/激活/框架开销）。商品 FP16 1024 维缓存约 1.77 GB。小规模先用抽样词表，执行前重新确认 GPU 占用并测峰值。

## 损失与训练阶梯

相似度为归一化点积除以任务温度；先沿用温度 0.07，两个任务各自配置。推荐使用真实历史—后续正反馈，语义使用经过校验的需求—商品；rating>=3 沿用已追溯的数据口径。LLM 不生成推荐正例或虚构用户历史。

主损失：`L=lambda_rec*L_rec+lambda_sem*L_sem`，两个任务每步各一批，先各 batch 64、权重 1:1。记录每任务有效样本曝光与共享梯度范数；语义样本很少时不能仅靠重复采样填平规模。

首先保持旧 smoke 的每例 32 个随机弱负例，屏蔽训练范围已知正例、重复及当前正例；明确低评分仍作为独立消融。这便于隔离骨干变化。批内负例是之后的效率对照：重复 ID 合并、同 query 已知多正例不能互作负例，采样概率仅从 train 推算；校正与实际采样器匹配，不给均匀采样或混合采样机械套用批内公式。未知语义相关商品仍有假负例风险。

语义能力保留可选：在固定的训练需求及候选上用原始 BGE 打分分布作教师，添加 `L_keep=KL(p_BGE||p_model)`；先关掉，再单独测试如 lambda_keep=0.1，并记录教师温度和候选集合。它保留原模型偏好，不代表人工相关性或保证推荐不受损。只在初始化验证失败排除后、残差模型仍有语义退化时引入。

按顺序执行可比较的实验：

1. **初始化门禁**：无训练时复现 BGE 基线分数；梯度路径、时间隔离、OOV、padding、导出前向一致性通过。
2. **推荐骨干对照**：原 BGE 历史均值；新残差骨干；新骨干加 ID。固定数据、负例、优化预算。旧部署模型另做真实 queryv2 回放，不引用历史数字替代。
3. **任务共享对照**：对选定骨干训练语义单任务、推荐单任务、共享 Item 联合模型；独立模型总预算与联合总预算明确披露。
4. **诊断与扩展**：分别尝试能力保留、批内采样、时间加权；胜出配置多种子复验，再考虑压缩、BGE 微调、q/u 融合。

优化器起点 AdamW，适配层学习率 2e-5、weight decay 0.01；ID 表不做全表 weight decay，学习率作为独立参数起点同为 2e-5。以上是待验证超参数，并非已证明优于原设定。固定 dev 每一定样本曝光评估，按两任务共同约束选 checkpoint，不按训练 loss 选；完整 test 只在配置冻结后使用。
