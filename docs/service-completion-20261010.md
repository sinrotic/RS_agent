## 已完成的用户流程

| 场景 | 当前行为 | 验收范围 |
| --- | --- | --- |
| 刷新或返回对话页 | 从服务端恢复原 Session、文字、公开回答块和推荐交付；支持历史切换及新建 Session | 浏览器 HTTP 夹具及服务端恢复测试 |
| 发送后丢失响应 | 原消息重试沿用 `client_turn_id`，已持久确认的结果直接返回，避免再次调用模型和推荐；消息内容冲突返回 409 | 同进程和服务对象重建后的持久记录回放测试 |
| 模型调用失败 | 记录 `TURN_FAILED`，历史展示固定公开提示，下一 Turn 可以继续；无确认最终答案的重试返回 409 | 模型失败及重建后恢复测试 |
| 停止生成 | 浏览器取得请求标识后调用归属受限的服务端中断接口；进入模型调用前已登记中断上下文 | 服务端早期中断及浏览器真实流式 HTTP 夹具 |
| 偏好管理 | 撤销最近反馈、删除单个商品偏好、页面确认后清空；反馈待应用时等待同步 | 浏览器撤销和清空流程；既有反馈闭环测试 |
| 推荐或排序不可用 | 推荐交付失败时保留文字对话，返回空商品和明确提示；排序降级状态贯穿 REST、SSE、历史与界面 | 离线依赖、状态投影及浏览器提示测试 |
| RAG 或推荐工具不可用 | 短时缓存就绪探测结果，隐藏失效工具并阻止执行；两次工具失败后仅允许最终回答阶段 | 依赖离线及恢复、工具执行及失败预算测试 |
| 公开数据边界 | 聊天、流式回答、历史和旧 `/turns` 路径仅返回公开答案；内部工具记录仍由平台接口读取 | Controller 与公开投影契约测试 |

浏览器只保存当前 Session ID，不把聊天正文或密钥存入 localStorage。已结束 Session 在页面中只读。历史归属校验和 Session 列表查询保留 Account、Profile User 的隔离边界。

## 运行保障与发布产物

各 Java 服务已加入 Prometheus registry，部署配置开放内部指标入口。新增 Prometheus、Alertmanager 和三条告警规则，覆盖指标不可达、HTTP 5xx 比例和反馈投影重试失败。官方 `promtool`、`amtool` 及 Compose 配置校验均通过。端口仅绑定服务器回环地址，默认告警接收器保留本地控制台记录，外部通知尚未配置。

新增就绪检查、工作区源码与产物哈希清单、发布 ZIP 打包工具，以及 MySQL 应用表备份脚本。隔离 MySQL 的实际备份恢复检查通过：恢复 2 条测试账号、1 条 Session 和 2 条反馈，确认 Catalog 表不进入备份，并清理临时容器与数据卷。该结果验证脚本可用性，不代表正式数据、Scylla 或异地恢复已经验证。

本地 Qwen 启动预算默认从 4K 调整为 16K，并拒绝更小容量；就绪检查在选用本地模型时才核验其容量。服务器现有本地 Qwen 仍报告 4K，未重启。已停止的正式 Agent 实际使用远端 GPT 接口，因此不能把本地模型容量当作正式停机原因。

发布包位于 `outputs/service-completion-20261010/release/service-release.zip`，配套 `release-manifest.json` 和 `SHA256SUMS`。包包含 12 个可执行服务 JAR、前端、SQL 和部署工具；默认发布模式仍为 `recommend`。源码清单包含当前工作区的未提交 Java 相关源码，不能把包描述为仅由 Git HEAD 构建。运行 `.env` 和密钥不进入包。
