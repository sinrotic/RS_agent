# 三塔小规模实验：2026-10-11

结论：已在远端独立 GPU 上完成样本生成、BGE 编码、三个训练对照及两个诊断。梯度路径正确，但当前小样本训练明显损害检索效果，**不晋级、不替换现有召回**。此次只能证明流程能运行，不能判断三塔架构的最终收益。

## 环境与资源

- SSH 主机 `server`，物理 GPU 2：RTX 4090，24,564 MiB。启动前占用约 15 MiB、利用率 0%；GPU 0/1 有其他任务。本次进程均固定 `CUDA_VISIBLE_DEVICES=2`。
- Python 3.12.3、PyTorch 2.11.0+cu128、Transformers 5.12.1、Sentence Transformers 5.6.0，复用现有环境，没有安装依赖。
- `/home` 仅余约 13 GB；产物放在 `/mnt/data/luo/remote_runs/three_tower_20261011_smoke_v2/`。失败的首版生成保留在相邻 `three_tower_20261011_smoke/`。
- 生成器为本地 Qwen3.5-4B，BF16、SDPA；缺少可选快速内核，使用已有 PyTorch 回退路径。生成期间观测 GPU 占用约 9.6 GB，这是 `nvidia-smi` 设备读数，不是精确 allocator 峰值。20 件商品后主动终止自有生成进程，保留完整的前 40 次输出；未记录完整生成峰值和总耗时。
- BGE-M3 冻结编码 4,820 件商品和 26 条需求，最大长度 256，batch 32：实测约 **17 秒**，PyTorch 峰值分配 **2.59 GiB**。
- 缓存向量上的 200 步语义/推荐/联合训练分别约 **2.0 / 2.8 / 4.6 秒**，最大分配约 **0.06 GiB**。不含 Python 启动、CUDA 上下文、生成和编码，因此不能拿这个数估计 BGE 微调成本。

环境快照在 `environment.json`，编码统计在 `encoding_metrics.json`。

## 数据与正负样本

输入沿用已有 `amazon_2023_sciomc_twotower_recent2y/smoke/`：1,000 用户、4,820 商品，构造 2,880 个训练前缀和 1,000 个留出目标。推荐留出是原 train smoke 内的每用户最后一个正例，**不是正式 valid/test**；用户切片来自已有文件顺序，不能推广到全量分布。

追溯原远端 `amazon_2023_recall_clean_full/stats.json`，`config.positive_rating_threshold=3.0`。本轮保留原口径：3–5 星为正反馈，1–2 星为低评分负反馈；并非采用清洗代码当前默认阈值 4.0，也不把这些评分称为本产品真实购买日志。

每个样本用目标发生前的正反馈历史预测后续正例；相同时间事件不互为历史。历史最多 50 件。推荐负例对照：

1. 基础组：32 个随机未观察商品，屏蔽训练集合已知正例和当前目标。这些是弱负例，仍可能包含潜在喜欢的商品；不读取留出目标帮助屏蔽。
2. 低评分组：优先放入最多 4 个目标时间之前的低评分商品，再以随机负例补足 32 个。2,880 个训练样本中 538 个有可用低评分负例。此混合采样为初步启发式，没有做采样概率校正或可靠性加权。

商品向量只用标题、features、description；没有使用评论正文、聚合评分或用户 ID embedding。元数据是静态快照，尚未解决历史可见性和商品近重复审计。

## 语义生成与质量调整

首版同时生成双语 JSON，出现语言错标、照抄标题、格式错误，已停掉并保留原始输出。第二版改为逐商品、逐语言生成，并要求提供原文字段证据。

准备列表包含 100 件商品；实际第一批只完成 20 件、40 条尝试。36 条通过格式、语言和引用检查，4 条拒绝。Codex 再逐条检查这 36 条，剔除 10 条，留下 **26 条（训练 16、留出 10）**。这是模型辅助检查，**没有人工评审**。

典型问题：48 mm 被转换成 48 张；S-Pen 无线充电被写成保护壳无线充电；VESA 转接板被写成完整电视挂架；总充电功率和单端口功率含糊。其他剔除项包括型号清单照抄、中文商品类型歧义和遗漏约束条件。因此引用存在性不是事实蕴含校验，当前生成器不能无审核扩量。

`agent_review.json` 保存每条保留/剔除的 query、理由、审核者类型及原输入哈希。远端保留 `generation_raw.jsonl`、`generation_rejects.jsonl`、`semantic_automatic.jsonl` 和最终 `semantic.jsonl`。按精确标题哈希组预先分割；未做系列商品去重；推荐任务可见语义留出商品，属于传导评估。

## 训练与梯度

冻结 BGE 1024 维特征。Query 和 Item 为独立 1024→128 线性投影；User 为历史向量均值→256→128 MLP。输出归一化，温度 0.07，AdamW 学习率 2e-4，batch 64，梯度裁剪 5，种子 42。推荐采样使用独立种子 43。

语义单任务、推荐单任务、联合模型采用相同初始化和各任务采样流。联合每步两个任务各取一批，分别反传后做一次更新：`L = L_sem + L_rec`。每个启用的任务在 200 步中看见 12,800 个样本（重复采样）；联合总样本曝光和计算量高于任一单任务，不声称总计算预算相等。

实测梯度断言通过：语义损失更新 Query/Item、不直接更新 User；推荐损失更新 User/Item、不直接更新 Query。共享 Item 的变化会间接改变另一任务的匹配关系。这证明参数路径，不证明两塔已具备互补性或不存在表征退化。

## 实测结果

候选集统一为 4,820 件商品，精确检索。推荐按 1,000 个用户各一个留出目标计算 Hit@100；语义按仅 10 条留出需求计算来源商品 Hit@10（中文 6、英文 4）。来源商品不是唯一相关商品，**该指标不是语义相关性金标**。

| 配置 | 推荐 Hit@100 | 语义来源 Hit@10 |
| --- | ---: | ---: |
| 原始 BGE 1024 维；推荐使用历史均值 | 14.7% | 90%（9/10） |
| 128 维随机初始化、未训练 | 2.3% | 60%（6/10） |
| 语义单任务，200 步 | 不作推荐基线 | 0%（0/10） |
| 推荐单任务，200 步，随机负例 | 7.4% | 不作语义单任务基线 |
| 联合，200 步，随机负例 | 7.2% | 20%（2/10） |
| 推荐单任务，200 步，加入低评分负例 | 8.5% | 不作语义单任务基线 |
| 联合，200 步，加入低评分负例 | 7.5% | 20%（2/10） |
| 语义单任务，20 步，事后诊断 | 不作推荐基线 | 10%（1/10） |
| 推荐单任务，20 步，事后诊断 | 3.1% | 不作语义单任务基线 |
| 联合，20 步，事后诊断 | 2.8% | 20%（2/10） |

原 BGE 与新模型的维度、用户结构不同；它是原能力保留参照，不能把全部差异归因于多任务。128 维单任务与联合对照才用于观察共享影响。非本任务单任务分支虽有原始诊断值，但请求塔没被该任务训练，因此不作为正常基线。

语义训练损失几乎为零而留出退化，支持小样本过拟合的判断。随机投影初始化已损失部分语义能力（9/10→6/10），随后训练进一步损坏（6/10→2/10）。缩短到 20 步也未恢复原能力。推荐学到了超过随机初始化的信号，但仍低于简单历史均值。低评分负例在本次切片上改善推荐数字，但只有一个种子，不能认定稳定收益。

完整数据：`results.json`、`results_explicit_negatives.json`、`results_short_training.json`。没有开展线上双塔 queryv2 回放、完整多路并集比较、融合查询评估、人工语义评估或 BGE 微调；不能宣称超过现有核心链路。

## 下一阶段调整

1. 先修数据：建立商品类型、属性和约束结构；生成器负责表达改写，校验数值、单位、配件关系和条件。扩大到约 1,000 件商品之前，先用有代表性的质量样本和人工评审确认可靠率。保留中英文分桶，不靠同一生成器自评分替代人工。
2. 加能力保留对照：冻结原始向量参照，比较更保守的投影初始化、蒸馏约束和残差结构；分别改变结构、学习率或任务权重，避免一次混改无法归因。本轮未证明缩短训练足够。
3. 采用正式时间分割和稳定用户采样，补旧双塔及现有多路召回回放；关键配置多种子复验。保持明确负反馈与弱负例来源可追踪，再评估困难负例。
4. 在冻结 BGE 的联合学习保住两项能力后，再进入 BGE 微调和融合查询。当前结果不足以支持直接扩大训练。

远端 `three_tower_smoke_200step.py` 保存第一轮精确代码，SHA256 与 `reproducibility.json` 一致。仓库当前版本仅增加训练前指标记录，用于 20 步诊断；短训练目录也保存代码哈希。所有数据、向量、checkpoint 的首轮哈希见 `reproducibility.json`。各目录保留三个模型权重与训练日志，未部署。

```bash
  /mnt/data/luo/remote_runs/three_tower_20261011_smoke_v2/three_tower_smoke.py \

```
