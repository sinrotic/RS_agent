# 完整推荐流程优化与验收（2026-10-10 至 2026-10-11）

本轮完成提交存储调整、多样性筛选的特征复用、本地模型上下文及最终输出预算修复，以及模型 HTTP 客户端复用。最终关闭计时探针的测试中，**完整热推荐中位耗时 198ms，8 用户并发中位耗时 330ms**。相较上一轮机械盘环境的 790ms、1402ms，分别下降约 75%、76%。这说明明确品类、计算缓存命中的推荐已进入约 200ms 的范围；复杂推荐、首次调用和冷计算仍需秒级时间，不能承诺全部单轮对话低于 300ms。

## 实际改动

1. **MySQL 保持落盘保障，提交相关存储迁至 NVMe。** 原实例约 23.37GiB，现有 NVMe 分区不足以安全容纳完整副本。完整停机冷备、逐文件 SHA-256 核验后，将约 285MiB 的主目录文件复制到 NVMe；已有 `rs_agent` 库目录继续挂载原机械盘。redo、binlog、doublewrite、undo、系统表及新建数据库位于 NVMe。镜像 8.0.45、server UUID、36 张表名和非 Amazon 大表的精确行数核验通过，两次启动验证通过。`innodb_flush_log_at_trx_commit=1`、`sync_binlog=1`、binlog、doublewrite、fsync 保持原值。
2. **多样性筛选复用单次调用中的商品特征。** 缓存标题 token、品牌和型号，按商品对象身份区分重复 ID 的不同内容，保持原排序、相似性阈值、品牌上限和探索行为。36 组优化前固化用例的商品顺序完全相同。8 个带探针热请求中，该阶段均值从上一轮约 38ms 降至 6.37ms。
3. **GPU 1 本地 Qwen 的窗口由 4096 调整为 16384。** 实测复杂首轮输入约 9–10K tokens，旧配置无法覆盖。显存比例由 0.85 调至 0.78，为辅助 BGE 留出空间；保持 BF16、prefix caching、工具解析及结构化输出。7 类 JSON / 工具输出兼容探测通过。
4. **仅最终回答步骤支持独立的输出上限。** 新增 `RS_AGENT_FINAL_ANSWER_MAX_TOKENS`，通用默认 0 以保持既有行为；本地 Qwen profile 默认 4096，QA 显式设为 4096。普通工具步骤仍使用原 1200 预算。旧模型的最终工具参数曾在 `finish_reason=length`、1200 tokens 处截断，导致 JSON EOF；增加最终预算后，普通推荐和连续三轮对话均可完成。预算不会强制输出固定长度，也不通过缩减推荐内容提速。
5. **模型网关复用两个 RestClient。** embedding 与 rerank 不再逐请求重建客户端。只读推理遇到 `ResourceAccessException` 时使用同一输入重试一次；HTTP 500、响应解码错误不重试，第二次失败仍按原语义记录 FAILED / 返回 503。新增单测覆盖输入相同、重试有界及 HTTP 错误不重试。

## 测量口径与结果

请求经过真实 Gateway 鉴权、User Session、Agent、推荐服务、训练 DeepFM、BGE、Milvus 和 Catalog，实际写入 MySQL、Scylla 与 Redis。计时从发送聊天 SSE 开始，到最终回答、SSE 结束及 5 个商品详情全部查询完成。注册、登录、新 Session 创建、事后历史及 Trace 检查在计时之外；未测浏览器渲染或公网往返。

## 主要等待变化

带探针的 8 个热请求中，Agent 四次 MySQL commit 均值由上一轮 420.5ms 降至 55.0ms；User 自动提交 SQL 约 15.1ms，推荐交付事务约 20.7ms。DeepFM HTTP 约 9.09ms；BGE 评分缓存命中约 0.42ms。JDBC commit 表示客户端等待，未直接测量服务器 fsync。调用树互斥计时闭合，服务内部阶段没有与外层 HTTP 重复相加。

下一步若继续压缩耗时，应优先研究不同冷 query 的 BGE 排队、保留完整候选的批处理及普通 Agent 模型生成。8 并发热请求仍有提交、连接池和服务间调用等待。本轮保留现有权威记录、投影提交和反馈事务；不能靠跳过持久化或强行将复杂需求送入快速回答来实现指标。

## 正确性与失败记录

验收检查每次返回 5 个不同的真实商品、独立交付 ID、训练 DeepFM / BGE 参与、无排序降级，以及历史最后一轮为 FINAL_ANSWER。Scylla 权威事件为 seq 1–4，MySQL Session `last_seq=4`、Turn `first_seq=1/last_seq=4`；相同 client_turn_id 返回完全相同的回答和交付。LIKE 反馈实际 APPLIED，重复提交去重；删除 Redis 热键、重启四个 QA 服务后，历史与重试结果完全相同。

失败证据保留并与最终验收区分：

- 1200 输出预算阶段，普通推荐 5 次中有 2 次 SSE 失败；另一次同步诊断返回 500。模型元数据及同步异常确认最终工具 JSON 截断。修复后多轮复测通过，但长输出耗时依然可能达到 20–30 秒。
- 网关连接复用前的 33 个请求全部完成，其中 1 个发生 `model_rank_unavailable`。模型 Trace 为 4ms FAILED，BGE 未收到相应请求；当时未保存底层异常类型，**无法严谨认定具体连接故障原因**。当前客户端减少连接冷建并处理短暂 I/O 失败，最新完整复测没有复现此降级，不代表故障已被穷尽证明消除。
- 一次最终测试批次的 38 个请求因测试账号令牌正常过期而在创建 Session 时收到 401，尚未进入推荐流程。保留该批次结果，测试工具通过真实登录更新相同账号令牌后重跑；业务鉴权规则未修改。

此前所有完整流程试验及诊断共保存 151 个新 Turn 尝试：148 个完整完成、3 个失败，其中 1 个完成请求发生上述排序降级。过期令牌批次单独保存，不计入已进入聊天流程的新 Turn 数量。

## 测试与部署状态

三个 Java 模块共 348 项测试，347 通过、1 跳过，无失败或错误；模型启动工具另有 19 项测试通过。业务构建 SHA-256 与最终 QA 实例一致。工作区另有偏好投影相关修改，本轮最终 Rec 构建已包含并验收其当前版本；不将这些修改归为本轮性能改动。

正式 MySQL 挂载与 GPU 1 本地模型配置已调整；优化后的 Agent / Recommend / Model JAR 在独立环境验证。**正式业务容器保持原停机状态，未覆盖其业务 JAR，也未替换原云模型 provider。** QA 容器、数据库、数据库用户、Scylla keyspace、账号令牌和私有环境文件已删除，临时 BGE 及模型元数据探针已停止；本地 Qwen 保持 16K 配置运行，GPU 0/2 的原训练进程继续运行。

完整冷备保留在远端 `db/mysql-cold-backup-20261010234436`。迁移后的原 `db/mysql/rs_agent` 被新实例继续使用，因此旧主目录不再是可直接启动的一致备份。回滚必须停写、恢复完整一致副本；产生新业务写入后，应先备份当前双挂载实例。不得简单切回旧主目录或混用新旧 redo 和表文件。操作细节见 [基础设施说明](../../../java_agent/deploy/remote/infra/README.md)。
