# 商品残差模型：推荐单任务验证

日期：2026-10-11。已完成商品残差骨干、推荐单任务对照、独立用户确认及三塔技术对照。推荐在有界候选、活跃用户范围内获得正向证据；调整版三塔保住了本轮推荐指标，但尚无正式语义质量提升结论。未部署。

## 实现

`three_tower_residual.py` 实现三个独立的 1024→256→1024 残差 MLP，BGE 冻结。Item 向量为 `normalize(x+MLP_item(x))`；User 消费经当前 Item 编码器变换的历史，取均值后输出 `normalize(h+MLP_user(h))`；Query 实现相同形式的独立适配器，但本轮推荐单任务不训练它。

最后一层零初始化，第一层正常初始化。每批将历史和候选商品 ID 合并去重，只计算一次共享 Item 前向，并保留历史路径的梯度。ID embedding（64 维）、固定 Item、历史时间加权为独立开关。ID 分支使用随机表＋零投影，未知 ID 的贡献严格为零。

初始化全候选分数与 BGE 基线最大误差约 2.98e-7；旧 smoke 的两个名次受近乎平分/重复归一化影响，Hit@100 一致。最初要求排名逐位相等的断言因此中止过一次，尚未训练；已改成数值误差门禁并显式记录排名差异。平局采用保守排名，不能将本轮 Hit@10 与旧脚本的乐观平局处理数字混为同口径。

训练起点：AdamW 2e-5，batch 64，每例 32 个均匀随机弱负例，温度 0.07，梯度裁剪 5。屏蔽训练期已知正例，不读取验证目标修正采样。ID 表无 weight decay。评分>=3 的既有正例口径保持不变。候选没有明确负反馈标签，因此采样商品不等于用户不喜欢。

## 第一阶段：既有程序 smoke

沿用原 1,000 用户、4,820 商品、2,880 训练前缀。该留出仍在原 train smoke 内，不是正式时间验证。

| 配置 | 150 步 Hit@100 | 200 步 Hit@100 |
| --- | ---: | ---: |
| 未训练 BGE 历史均值 | 14.7% | 14.7% |
| 残差，seed 42 | 16.3% | 15.8% |
| 残差，seed 43 | 16.2% | 16.1% |
| 残差，seed 44 | 16.2% | 15.9% |
| 残差＋ID，seed 42 | 16.3% | 15.7% |

三个种子方向一致，说明此前随机压缩模型的明显退化已经缓解；不能仅凭这些数字证明全量效果。根据这一阶段选取 150 步作为后续多种子对照点；同时探索较长训练的趋势。

## 第二阶段：官方时间窗口，有界候选库

源为远端 `amazon_2023_recall_recent_2y_1m_3m`。训练窗口截止 2023-05-15 UTC，验证窗口为 2023-05-15 至 2023-06-15，均为半开区间；未读取最终 test。扫描 6,826,801 条训练用户序列，687,556 人有至少 3 个保留正例，按稳定哈希选取 10,000 人，构造 38,756 条前缀样本，每人最多 20 条。

最初仅在这 10,000 人中寻找验证事件，仅有 64 人，故没有据此判断效果。改用独立验证队列：在满足训练历史条件且验证月有正反馈的人中按稳定哈希选 1,000 人，取首次验证正反馈。资格需要验证期有正反馈，但不根据目标身份或可召回性筛用户。与训练用户重叠 64 人；其余用户虽未参与优化，仍有训练期历史可编码。

候选库为两队列的训练期历史商品＋train catalog 的固定哈希子集，共 45,032 件；没有把缺失的验证目标补入候选库。源构建器 `recent_window_materializer.write_window_items` 将 canonical_items 限定为训练期出现商品。327 个验证目标有覆盖，673 个保留在分母中计为未命中，MRR/nDCG 贡献为零。本轮是有界候选 pilot，不是全商品库或线上 queryv2 评估。

| 配置 | 150 步 Hit@100 | 说明 |
| --- | ---: | --- |
| 未训练 BGE 历史均值 | 3.0% | 所有人的基线 |
| 残差，seed 42 | 3.6% | 单种子配对区间 +0.1 至 +1.2 个百分点 |
| 残差，seed 43 | 3.2% | 区间包含零 |
| 残差，seed 44 | 3.5% | 区间下界为零 |
| 残差＋ID，seed 42 | 3.6% | 本训练预算未显示增益 |
| 固定 Item，只训练 User，seed 42 | 3.6% | 没有明显优于联合训练 User/Item |
| 历史 180 天半衰期，seed 42 | 3.2% | 对应未训练加权基线为 2.9% |

150 步三种子平均为 3.433%，相对原均值基线增加 **0.433 个百分点**，不是 0.433%。逐用户先平均固定三种子的命中，再做 2,000 次配对 bootstrap，95% 区间为 **-0.067 至 +0.967 个百分点**。区间包含零，不能判胜。该区间不代表对任意随机种子分布的置信，也未做多配置选择校正。

延长到 600 步未显示稳定额外收益；seed 42 普通残差最终为 3.4%，固定 Item 也是 3.4%，180 天加权也是 3.4%。未依据这些结果反复选择新的学习率。ID 分支学习较慢，本结论只适用于当前初始化、学习率和预算，不代表商品 ID 没有价值。

## 第三阶段：冻结模型的独立用户确认

冻结无 ID、均值历史、150 步的三个种子 checkpoint。使用剩余满足相同资格但不在原 1,000 人队列中的用户，按预定哈希规则最多取 3,000 人，实际 **2,970 人**。不再训练、不根据确认结果选择 checkpoint。

候选库固定为原 45,032 件。新增 10,704 件历史商品只用于用户历史编码，不加入候选集合；库外目标仍是未命中。确认集与调参集用户交集为零。它仍来自同一验证月份，是独立用户确认，不是最终跨时间 test，也不能推断所有用户流量收益。

独立确认结果如下，候选目标覆盖为 34.65%，完整分母 2,970 人。

| 配置 | Hit@100 |
| --- | ---: |
| 未训练 BGE 历史均值 | 2.761% |
| 残差 seed 42 | 3.098% |
| 残差 seed 43 | 3.098% |
| 残差 seed 44 | 3.165% |
| 固定三种子平均 | 3.120% |

平均增加 **0.359 个百分点**，相对约 13.0%；固定三种子平均后的逐用户配对 bootstrap 95% 区间为 **+0.090 至 +0.673 个百分点**。这是未参与调参用户上的正向证据，支持进入下一项有界技术实验，不等于生产路由晋级或全量/冷启动泛化已经完成。结果在 `confirmation_results.json`。确认阶段耗时约 117 秒，包含重扫历史、补充历史编码和三个既有模型评估，无训练。

## 第四阶段：三塔对照与调整

推荐确认通过后，恢复此前保留的 26 条语义需求，重新按商品 ID 映射到本候选库。原有 6 条已覆盖；另外加入 12 件训练期来源商品，所有单任务和联合对照统一使用 **45,044 件**候选。新增商品没有增加推荐验证目标覆盖。新增商品使用对应版本的已缓存 BGE 特征，重叠商品逐一断言文本完全一致。不能把旧 smoke 的 item_index 直接复制到新候选库。

此处仍只有 **16 条语义训练需求、10 条来源留出需求**，无人工金标。它们仅能诊断技术退化；训练重复曝光很高，不能验收真实语义质量。三种模式从相同零残差初始化重新训练，各任务使用相同采样流，每项启用任务都看 150×64=9,600 个样本；联合总计算和总曝光约为任一单任务的两倍。不是在推荐 checkpoint 上继续训练，因此隔离的是同骨干的任务共享差异。

第一轮 seed 42：

| 配置 | 推荐 Hit@100 | 语义来源 Hit@10 |
| --- | ---: | ---: |
| 原 BGE 均值/语义基线 | 3.0% | 5/10 |
| 推荐单任务 | 3.3% | 5/10（Query 未训练，观察能力保留） |
| 语义单任务，原学习率 | 非推荐基线 | 3/10 |
| 联合，语义权重 1 | 3.4% | 3/10 |
| 联合，仅将语义权重降为 0.1 | 3.2% | 3/10 |
| 联合，权重 0.1＋Query 学习率 2e-6 | 3.3% | 6/10 |

先改变损失权重，再独立降低 Query 学习率，其余适配层仍为 2e-5。不能以为缩小损失权重就会让 Adam 的独占 Query 参数更新幅度同比缩小；本轮降低损失权重也确实未解决来源命中退化。这些调整使用了同一个极小代理留出集，属于事后开发诊断，不能把之后的数字当最终 test。

补上相同低 Query 学习率、相同语义权重的语义单任务，并复验三个种子：

| 配置 | 推荐 Hit@100，seed 42/43/44 | 语义来源 Hit@10，seed 42/43/44 | 平均语义 MRR |
| --- | --- | --- | ---: |
| 原 BGE | 3.0% | 5/10 | 0.381 |
| 推荐单任务 | 3.3% / 3.5% / 3.4% | 5/10 / 6/10 / 5/10（保留诊断） | 0.400 |
| 语义单任务，调整参数 | 非推荐基线 | 3/10 / 3/10 / 3/10 | 0.134 |
| 联合，调整参数 | 3.3% / 3.5% / 3.4% | 6/10 / 6/10 / 6/10 | 0.367 |

联合与推荐单任务平均 Hit@100 差为 0；配对用户区间为 -0.1 至 +0.1 个百分点，未做多配置选择校正，不能据此宣称严格等价。联合的来源 Hit@10 在极小集合上较好，但 MRR 低于原 BGE 和推荐单任务的语义保留诊断，因此没有“全面语义提升”的结论。平均相同 Hit@100 也不代表逐用户候选完全相同。

`joint_comparison.json` 保存三种模式的种子、运行目录、指标和配对差；`joint_data_manifest.json` 保存候选扩展口径。所有三塔结果只使用原 1,000 人开发队列评估推荐，**没有再读取 2,970 人确认集来调整三塔**，也没有对三塔宣称独立确认通过。

下一步应补足高质量语义训练与独立人工相关性评估，再冻结三塔配置重新确认。保留当前通过有界推荐确认的纯推荐模型作为对照，暂不继续增加网络复杂度或微调 BGE。

## 资源、产物与限制

- 使用物理 GPU 2：RTX 4090 24GB，启动前 15 MiB、利用率 0%；沿用现有 Python/PyTorch/BGE 环境。
- 45,032 商品 BGE 编码约 118.6 秒，allocator 峰值 2.59 GiB；特征缓存 FP32，推理 FP16，最大长度 256。
- 推荐主实验 600 步含评估约 5.4 秒，allocator 峰值约 0.55 GiB；不包含进程启动、数据预处理和编码，也不代表 BGE 微调成本。
- 远端根目录：`/mnt/data/luo/remote_runs/three_tower_product_v3/`，保存独立运行目录、日志和 checkpoint。初期 smoke 记录代码哈希，后续训练额外保存完整运行代码快照及输入哈希。后续运行写新目录，不覆盖现有结果。
- 本地 `experiment_summary.json` 保存 **22 组训练运行**摘要；`data_manifest.json` 保存切分、覆盖与哈希；`recommendation_gate.json` 保存原队列三种子汇总（不能替代后来的独立确认）；`encoding_metrics.json` 保存编码成本。
- 专项测试 **14 passed**，覆盖零初始化、历史梯度、双任务梯度隔离、ID/OOV、缓存前向一致性、时间隔离、弱负例屏蔽、缺失目标分母、近期权重，以及推荐/联合两种 CLI 的实际训练与 checkpoint；四个实验脚本编译通过。未运行无关服务全套测试。
- 数据继承上游静态元数据和用户商品去重方式；训练序列最多 50 件，负例屏蔽无法覆盖更早的未保留正例。候选覆盖、正反馈事件资格和切片偏差均限制推广。
- 当前没有新的足量语义金标。旧 26 条需求只能用于上述技术诊断，原库仅覆盖其中 6 条需求的来源商品，已显式扩展候选并重新映射；不能将这些结果当正式语义相关性对照。

没有修改已部署召回路由、模型或索引。完整候选域和旧双塔线上前向回放仍是后续晋级条件。
