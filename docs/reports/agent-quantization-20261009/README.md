# GPU 1 上的 Agent 量化验收

测试日期：2026-10-09。使用服务器上的原始 Qwen3.5-4B 权重和当前工作区 Java Agent，先验证量化后的实际工具路径，再决定是否推广。磁盘权重未改写，GPU 0、2 的训练任务未调整。

## 最终结论

**没有保留启用量化的正式部署。** 量化接入、配置切换、回归脚本和部署停止行为修复已完成，但分层 W8A16 在隔离实例中的改善未稳定复现于正式重启后的服务。部署验收失败后关闭推广门禁，恢复原 BF16 启动脚本和 `.env`；隔离压测数字保留为实验结果，不能作为当前服务收益。

原远端配置仍为 4096 上下文，与当前完整 Java Agent 请求不兼容；本次为保持原部署状态而精确回退，未把隔离测试的 16K 或 256 流额度留到原服务。代码中的 `.env.example` 推荐 16K，实际正式 Java/数据库/推荐依赖配置仍需另行接通验证。

## 对照条件

模型使用 RTX 4090 GPU 1、vLLM 0.24.0、16K 上下文、0.85 显存利用率、prefix caching、XGrammar 严格工具参数约束及 qwen3_xml 解析器。thinking 关闭、温度 0、每次调用最多 1024 输出 token。BF16 与量化使用同一份本地权重，不改变 Agent 提示词或工具定义。

Java 测试实例监听 loopback 18204，堆上限 2 GiB，模型 streams 与 active loops 均为 256，模型额度等待 200ms；内存会话、固定候选，不启用发现和持久化。JAR SHA256 为 `12f21aaabde344bf2d8484c88a21828951b4a84cc55d9735ee3c1e6a0e1f0677`。在线推荐/RAG、数据库、网关仍未启动，结果不能当作完整购物业务容量。

混合场景及 SSE 完成规则沿用[原并发报告](../agent-capacity-20261009/README.md)。额外读取每个真实会话的工具记录，分别统计轮次完成率和工具无失败率；不能把最终降级回答算作工具链健康成功。每档并发重复 3 批，先通过低并发和单请求回归才继续升档。

## 分块 FP8 与 W8A16

原生 `fp8_per_block`、仅 MLP 配置在 RTX 4090 上选择 Triton FP8 分块内核。加载占用降至 6.55 GiB，但图编译的 autograd 缓存出现 PermissionError；改用独立 VLLM_CACHE_ROOT 仍复现。关闭 autograd 缓存后又因编译产物不能序列化退出。没有生成就绪状态，也没有发起 Agent 质量或容量测试，不能将这组视作成功运行的量化配置。完整失败日志保留在服务器测试目录。

随后对相同 MLP 使用 FP8 分块权重、BF16 激活，即 Marlin W8A16。本次安装版本在 SM89 上须通过 `VLLM_TEST_FORCE_FP8_MARLIN=1` 选择该内核；这是版本相关的测试选项，不能作为跨版本通用配置。源码和启动日志确认实际选中的内核，不能只看 `--quantization fp8_per_block` 就声称激活也在使用 FP8。

W8A16 加载占用 6.58 GiB，结构化输出 7/7 通过，购物样本关键词 15/16，未匹配的一处仍明确说明缺少购买历史。最初只检查工具失败的三次单请求均通过，8 并发 24/24 结束，工具无失败率 100%，P95 4.723 秒、2.361 轮次/秒。然而普通建议请求 8/8 都只返回开场语，没有三条建议。这减少了生成内容，不能把吞吐提高视作有效性能收益。

回归脚本加入回答完整性后，对 W8A16 重复 3 次均失败：无 FAILED 工具，但 `answer_complete=false`。这组没有通过验收。保留最初只检查工具的结果用于解释验收漏洞，不用它推广模型。该消融支持激活量化可能影响工具路径的假设，但权重量化、内核和其他数值变化仍可能影响回答；不是单一根因的证明。

证据：[W8A16 实测配置](instance-model-fp8-w8a16.json)、[W8A16 压测](capacity-fp8-w8a16-8.json)、[W8A16 工具审计](tool-audit-fp8-w8a16-8.json)、[W8A16 回答审计](answers-fp8-w8a16.json)、[加强后的单请求回归](regression-fp8-w8a16-complete.json)。

## 通过隔离验收的分层 W8A16

保留 32 层模型的前后各 8 层，仅量化中间第 8～23 层 MLP 权重；激活、所有注意力、视觉及输出层仍为 BF16。实际使用 Marlin FP8 分块 W8A16 内核，加载占用 7.60 GiB，比 BF16 8.61 GiB 减少约 11.7%。可用 KV 缓存 9.16 GiB、244897 token，较 BF16 仅增加约 1.4%；额外内核工作区等运行时占用抵消了部分权重节省，不能把 11.7% 直接当作缓存或总显存节省。

共 720 个轮次全部完成，720 份工具记录全部无 FAILED，240 个普通建议回答全部完整。单请求重复 3 次也完整且无失败工具。结构化输出 7/7；短购物样本关键词 14/16，预算和购买历史两处同义表达与 BF16 基线一样不匹配，人工复核未发现计算、预算或尺寸事实新增回归。商品注入样本的共同完整性局限仍存在。

104 档 P95 降低约 25.3%，吞吐增加约 32.6%。同时，模型调用数从 BF16 的 422 降到 312，提示 token 从 2141502 降到 1509340，生成 token 从 50258 降到 45628。实际工具路径减少了加载技能后的追加轮次，回答仍有三条建议。因此这是该量化配置及工具路径变化共同产生的端到端结果，不能全部归因于 FP8 单个内核速度，也不能外推到必须检索商品的完整业务。

最高对照测试档为 104，没有继续寻找新配置的最大并发边界。16K、256 模型流、2 GiB Java 堆及内存会话这些条件仍然是结论的前提；正式 Java 服务默认额度没有因本次模型部署自动变成 256。

## 正式重启验收与回退

首次推广保持原部署的 `VLLM_PREFIX_KEEPALIVE=true`，使用持久化编译缓存；7 个结构化探针通过，但普通建议的新会话重复 3 次都出现额外技能加载及失败委派。每次约 8 次模型调用、1 个 FAILED 工具，回答虽然完整，仍不满足工具健康门槛。

只关闭定时前缀预热后再次重启，prefix caching 保持开启。3 次普通建议均为 2 次模型调用，没有 FAILED 工具，但第三次只给出开场语，仍不通过回答完整性门槛。不能由这个消融认定定时预热是唯一根因；编译缓存加载、混合模型缓存路径和数值变化等仍需进一步定位。没有修改 Agent 提示词、删除工具或绕过检查来强行启用。

本次因此停止推广，`acceptance.json` 的 `promote=false`。原部署脚本、`.env` 和原服务参数恢复，测试 Java 18204 实例停止。原模型目录未修改。复用此配置前必须重新通过完整回答和工具路径检查，并覆盖重启与热缓存状态；单次进程中的吞吐优势不够。

证据：[隔离验收记录](acceptance-isolated.json)、[最终拒绝推广记录](acceptance.json)、[定时预热开启时复测](regression-promoted-keepalive.json)、[关闭时复测](regression-promoted-no-keepalive.json)。恢复验证记录见 [deployed-state.json](deployed-state.json)。

## 部署支持与限制

启动脚本新增 `VLLM_QUANTIZATION`、`VLLM_QUANTIZATION_CONFIG`，JSON 作为单个命令行参数传递。默认 `auto`；回退原精度须清空量化 JSON。对照启动器核验 GPU 1、空闲请求数与进程身份，备份原脚本和配置，并在推广时校验部署文件未被其他操作修改、验收量化与前缀预热配置均和当前实测一致。启用接口的仓库代码保留，远端正式脚本已精确回退原版。

同时修复预热期间停止启动器时不能及时退出、预热子进程可能继续等待的问题。针对真实 bash 启动器的无 GPU 夹具，原脚本在 2 秒停止期限内失败，新脚本通过，且量化 JSON 保持一个独立 argv 参数。控制脚本对自己创建并核验的进程组发送停止信号，清理隔离实例的子进程，不扫描并停止其他训练任务。验证记录：[launcher-validation.json](launcher-validation.json)。

FP8 首次编译预热允许 600 秒等待，只有原有 7 个结构化输出探针全部通过才生成 ready 文件。KV dtype、GDN 状态、视觉模块均未调整；即使模型权重占用降低，vLLM 按 0.85 预分配后总显存仍约 19.8 GiB，收益主要体现为更多缓存空间。

完整 Agent 提示词超过原部署 4096 上下文。对照统一使用 16384，样例也调整为 16K；这项兼容性修正与量化参数分别记录，不能把 4K 请求失败和 16K 请求成功当作量化收益。

依据：[vLLM 在线量化文档](https://docs.vllm.ai/en/v0.24.0/features/quantization/online/)、[Qwen3.5-4B 模型说明](https://huggingface.co/Qwen/Qwen3.5-4B)。运行时行为以本次安装的 vLLM 0.24.0 源码、实际 argv、探针及工具记录为准。
