# YouTube 召回训练样本与本项目数据的对应关系

核对日期：2026-10-11。以下是历史论文公开方案，不代表 YouTube 当前线上实现。

## 2016：用历史行为预测未来观看

候选生成以完成观看作为正例，使用全站观看来源，包括站外嵌入。选定一个观看事件作为目标，输入仅包含它之前的动作；每用户取固定数量样本，避免活跃用户支配训练。负例是从背景分布采样的候选类别，配合重要性校正和交叉熵，并不要求用户明确点踩。[原文 §3.1、§3.4](https://research.google.com/pubs/archive/45530.pdf)

用户输入包括历史视频 ID 嵌入的均值，并可加入搜索词、地区、设备等特征。候选视频是 softmax 输出侧的可训练向量；这不是两个 BGE 文本编码器。论文的召回与曝光数据驱动的排序是两个阶段，不应混淆其样本。[原文 §3.2–3.5、§4](https://research.google.com/pubs/archive/45530.pdf)

## 2019：明确的内容特征双塔

该论文的 YouTube 场景是观看页推荐。左塔输入当前视频及用户历史，右塔输入候选视频特征，包括视频 ID、频道、主题等。历史 ID 嵌入取均值，同类 ID 嵌入共享。这里的 query tower 指用户及上下文塔，不等于自然语言需求塔。[原文 §3、§5.1](https://storage.googleapis.com/gweb-research2023-media/pubtools/5716.pdf)

点击提供正标签，观看参与程度提供样本权重；文中举例几乎未观看权重为 0、完整观看为 1。批内其他商品作为对比候选，用估计的采样概率校正 softmax logits。这说明召回也可有参与度权重，但不能把 2019 的设定倒推成 2016 的召回标签。[原文 §3、§5.1](https://storage.googleapis.com/gweb-research2023-media/pubtools/5716.pdf)

## 本项目建议：以下属于设计判断，不是论文结论

**真实用户商品序列与商品文本足以构建推荐召回训练样本；不必先生成用户描述，也不必有购买完成标签。** 前提是序列来自真实行为，保留用户归属、商品标识和可靠顺序，并明确行为的业务含义。

例如真实正反馈序列 `[A, B, C, D]` 可构造：

| 用户塔输入 | 正例商品 |
|---|---|
| `[A]` | `B` |
| `[A, B]` | `C` |
| `[A, B, C]` | `D` |

以上只是样本形式示例。实际训练与验证要按时间隔离，不能把验证目标或更晚事件回填进训练历史；不能先训练最后一行，再用它验证。商品文本经 BGE 编码后，可以作为历史商品和候选商品的特征。序列提供“什么行为之后发生什么”的监督，文本提供商品内容；二者承担不同作用。

若序列来自评论/评分，应称为预测后续评论或正反馈商品，不能直接声称预测购买。若序列完全由模型编造，则只能验证合成设定，不能据此证明真实推荐有效。

负例建议先采用随机未交互或批内商品作为弱负例，并屏蔽已知正例；此前低评分商品可以作为单独实验的负反馈。未交互不等于不喜欢。若改为批内采样，应记录对应采样分布，单独验证采样偏差校正，而非无条件套用公式。

下一步优先比较相同切分下的 ID-only、text-only、ID+text 三种推荐表示，检验本项目是否缺少可训练的协同信号。BGE 冻结文本均值只是其中一个基线，不等价于论文里联合训练的 ID 嵌入。推荐目标可使用真实序列；需要额外生成的是缺少日志的需求文本—商品语义监督，这两类数据来源应分开管理。

代码核对：现有 `python_agent/rs_core/offline/training/two_tower.py` 的 `_string_user_examples` 已按前缀构造目标；`_TorchYouTubeDNN` 使用 `Embedding.from_pretrained(..., freeze=False)`，并在用户 MLP 后加历史均值残差。本次三塔 smoke 使用固定 BGE 历史均值和无该残差的用户 MLP，二者不是相同推荐骨干。该发现不能单独解释退化原因，但后续对照应固定这些结构变量；这里没有声称当前线上部署采用此类的原始前向。
