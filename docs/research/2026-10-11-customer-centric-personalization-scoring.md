# 顾客视角的个性化购物评分规划

日期：2026-10-11。范围：回答当前 v5 是否足以评价真实购物与支持 Skill 自进化；本次仅形成研究与评分规划，不修改题集、评分器或上线门禁。

## 结论

现有 v5 可用于工具协议、明确商品约束和受控画像匹配的工程回归，但不足以作为真实顾客满意度指标或自动晋级 Skill 的唯一目标。问题不是缺少一个更复杂的加权公式，而是相关性标签、画像使用规则和澄清验收尚未充分独立验证。

“照我以前的习惯先给我选 1 款参考”把环境应提供的画像使用条件塞进了顾客台词，可能测到显式提示响应，而非自然购物中的适度个性化。后续应由环境分别提供 Account 与 Profile User 绑定、合法使用权限和历史证据；顾客只自然表达购物需求。当前意图及 Session Preference 优先，Profile Preference 保持弱信号，不能把历史频率自动提升为本次隐藏硬需求。这与 [CONTEXT.md](../../CONTEXT.md)、[ADR-0017](../adr/0017-feedback-event-authority-and-online-preference-projection.md) 及 [ADR-0018](../adr/0018-personalized-home-recommendation-route.md) 的边界一致。

## 一手来源核实：可以借鉴什么，不能证明什么

1. **ShoppingBench**：其商品相关性使用目标商品的标题相似、价格条件与特征命中，CAR 聚合部分匹配，ASR 要求条件全部满足。它支持可验约束的公式评分，并不直接验证真实用户满意度。当前公开实现与论文差异已在 [既有公式审计](2026-10-10-shoppingbench-formula-audit.md) 单独记录，本笔记不重复审计。[原论文 v4，Evaluation](https://arxiv.org/html/2508.04266v4)

2. **累计增益评价原始研究**：相关性先通过分级判断提供，再计算累计增益、位置折扣及相对理想排序的表现。因此，“NDCG 算得正确”与“输入相关性代表顾客需求”是不同问题。迁移推论：必须独立检查标签，不能用一个未经校准的历史频率公式同时充当偏好真值与唯一裁判。[Järvelin 与 Kekäläinen，2002，原论文出版页](https://doi.org/10.1145/582415.582418)

3. **推荐评价的选择偏差**：Schnabel 等指出，用户自选择和推荐系统的曝光策略使交互数据存在选择偏差，并研究倾向加权评价。迁移推论：历史正交互仅证明发生过该正向行为；不能把未交互商品自动视为不喜欢，也不能把下一次正交互当作唯一可接受商品。没有合适的曝光与倾向信息时，不应声称已实现无偏评价。[ICML 2016 原论文](https://proceedings.mlr.press/v48/schnabel16.html)

4. **EComAgentBench**：将需求分配到可见 query、工具可读 profile、脚本澄清三处，并按要求类型及信息来源诊断失败。可以借鉴来源可追溯的 rubric，但其 persona 是合成的陈述偏好，论文明确把行为历史的潜在偏好推断留作另一问题；关键词脚本澄清也不等于真实对话自然度。不能据此把本仓库历史代理视为已知个人真值。[原论文 v1，Sections 3–4、Limitations](https://arxiv.org/html/2606.17698v1)

## 当前实现证据与不足

以下是本地实现事实，不是上述论文结论：

- [profile_matching.py](../../python_agent/rs_core/offline/evaluation/skill_benchmark/profile_matching.py) 按类目与完整路径隔离历史，使用 `P(v)=count(v)/n`，折扣 `c=n/(n+2)×coverage`。该折扣是工程启发式，不是经校准的概率；文件明确记录 `not_observed_customer_satisfaction`。
- [profile_dataset.py](../../python_agent/rs_core/offline/evaluation/skill_benchmark/profile_dataset.py) 在画像参考任务中生成“照我以前的习惯”等台词；[dataset.py](../../python_agent/rs_core/offline/evaluation/skill_benchmark/dataset.py) 验证该文字条件。因此后续修复不能只改表达，还要同步调整画像适用规则。
- 少量历史仍可能让符合代理偏好的商品获得归一化满分。这个 100 分表示当前代理规则下相对最优，不表示有充分证据证明用户最喜欢它。
- [v5 人工校准报告](../../python_agent/benchmarks/skill_benchmark/v5/calibration/pending-report.json) 显示 `reviewed_pairs=0`、`valid_reviewed_pairs=0`、`passed=false`。现阶段未建立公式与独立人工判断的一致性。

## 建议四层评价，而非立即合成任意权重的总分

| 层次 | 评价对象与建议方法 | 必须避免 |
| --- | --- | --- |
| 硬门槛 | 当前明确预算、类目、必要兼容性、有效商品及事实依据；必要项违规不能被其他加分抵消；属性未知时允许恰当澄清或说明不确定 | 用历史偏好补偿预算或兼容性失败；把未知属性说成已验证 |
| 当前任务商品效用 | 可核实要求用公式检查；软需求与商品合理性用独立分级标签，再计算 NDCG@k；允许多款同等合理商品 | 预选商品 ID 作为所有任务的唯一答案；把标签不足当作低相关 |
| 画像条件增益 | 同一自然需求、相同商品环境，比较真实画像与去画像条件下、使用同一独立评价标准的质量差 `Δ`；另测当前意图覆盖历史、送礼与无关历史的稳定性 | 仅因两人得到不同商品 ID 就加分；单次正交互变成强偏好；评分本身随条件改变形成循环论证 |
| 对话与依据 | 必要澄清成功率、无谓追问率、当前反馈遵从率、无依据事实错误率；对低风险信息不足可允许先给保守选项并说明不确定 | 按历史次数阈值机械要求提问；奖励多问；必须复述标准问句才算正确 |

画像增益只在相关且足够支撑的历史证据可能提供帮助时解释为个性化收益；弱历史、跨类目历史与给别人购买应有单独报告。无关条件下需要稳定的是对有效需求的满足，不强制最终商品 ID 完全相同。

独立人工标签能检查推荐是否合理、事实是否准确及公式是否与评审一致，不能声称评审已知道真实个人的主观满意度。若使用 LLM judge，应先以人工盲审校准并保留分歧审计，不让同一生成逻辑自产题目、自定偏好并自证高分。

## 进入自进化前的验收顺序

1. 保留冻结的旧版本作工程回归；新版本去除显式画像触发台词，并记录需求、画像、澄清及商品事实分别来自哪里。
2. 补齐独立标注及场景覆盖：自用、送礼、当前偏好冲突、无相关历史、弱历史、关键兼容信息缺失；扩充真实独立用户，不能把同一用户的表达改写算作新独立样本。
3. 冻结评测标签与门槛，再在同模型、同工具快照、同预算下比较旧版与候选 Skill；按独立用户或画像对照簇统计不确定性，不将多次重跑当作独立顾客。
4. 晋级依据使用质量提升、硬门槛不退化、画像误迁移不增加及校准通过的联合判断。上述指标仍是离线代理；真实满意度与业务收益需后续真实反馈或线上实验验证。

本笔记未规定未经验证的总分权重，也未宣称某个固定样本量或置信区间阈值能自动保证业务有效性。
