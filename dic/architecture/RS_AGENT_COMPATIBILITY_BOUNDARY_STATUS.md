本文档记录五模块服务化迁移后旧目录的过渡状态。迁移原则是：新代码优先走 `rs_core/data`、`rs_core/online`、`rs_core/agent`、`rs_core/offline` 以及已收敛的 `rs_core.serving` / runtime worker canonical 入口；旧目录仅作为兼容层或存量实现来源，不能继续扩展为第二套主线。

退役等级用于支持 `RS_AGENT_POST_MIGRATION_HARDENING_PLAN.md` Phase 1 的 import 治理：

- **A 类**：纯 compatibility facade，可在调用点清零后删除。

- **C 类**：需要迁移的核心实现，必须拆到新模块后再退役。
- **D 类**：历史/探索入口，只保留归档或手动脚本，不进入主验证链路。

## 新代码约束

- 新 HTTP 入口放在 `rs_core.serving.api.online_app` 或 `rs_core.serving.api.agent_app`。
- 新 worker 入口放在 `rs_core.data.runtime.worker` 或 `rs_core.offline.runtime.worker`。
- 新 Agent/RAG 代码优先放在 `rs_core/agent`；新在线推荐代码优先放在 `rs_core/online`。
- 旧目录新增能力必须说明为什么不能进入新模块，并补迁移截止条件。
- `services` package 已删除；新 HTTP 入口必须使用 `rs_core.serving.api.online_app` / `rs_core.serving.api.agent_app`，新 worker 入口必须使用 `rs_core.data.runtime.worker` / `rs_core.offline.runtime.worker`。

## 删除前通用 checklist

1. 新 canonical owner 已存在并有 public contract。
2. 调用点已切换到新入口，旧路径只剩 whitelist facade 或 legacy tests。
3. 已有 parity test 和 smoke test。
4. import census / grep 证明无新增主业务依赖。
5. rollback path 明确：可恢复 facade 或保留旧实现版本。
6. 更新 `RS_AGENT_LEGACY_IMPORT_CENSUS.md`、工程叙事或 ADR。
7. 运行对应分层测试、ruff 和 `git diff --check`。
